Diseña eventos con nombre, detail, bubbles y composed para comunicar decisiones sin controlar al padre. En esta clase construiremos un selector de cantidad desacoplado; la meta no es memorizar una API, sino poder predecir el contrato antes de escribir código.

Un evento es una carta: nombre dice qué ocurrió, detail lleva datos y las opciones deciden hasta dónde viaja.

Este ejemplo no es el ejercicio disfrazado. un selector de cantidad desacoplado nos permitirá observar el mismo principio en un problema diferente y comparar decisiones.

Usa eventos para decisiones nacidas dentro del componente; usa propiedades para datos que entran. Si el problema no necesita esa frontera, una función o HTML normal puede ser una decisión más sencilla.

Nombra hechos, documenta detail y prueba desde la API pública. El error que más veremos es este: emitir órdenes al padre, omitir composed tras Shadow DOM o filtrar nodos internos.

Resuelve un selector de cantidad desacoplado desde la API pública hacia dentro. El código inicial conserva contexto, no la respuesta; deja que las comprobaciones guíen tu diagnóstico.
