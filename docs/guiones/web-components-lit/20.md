Reemplaza arrays y objetos al cambiar estado para que Lit detecte nuevas referencias y mantenga identidad. En esta clase construiremos un tablero de tareas que siempre se actualiza; la meta no es memorizar una API, sino poder predecir el contrato antes de escribir código.

Una referencia nueva es un sobre nuevo que avisa del cambio. Editar silenciosamente el contenido del mismo sobre puede pasar desapercibido.

Ahora pondremos el modelo bajo presión con un tablero de tareas que siempre se actualiza. Primero identifica los datos; luego el ciclo que actúa sobre ellos; al final comprueba la interfaz.

Prefiere actualizaciones inmutables en estado reactivo, especialmente cuando datos pasan entre componentes. Si el problema no necesita esa frontera, una función o HTML normal puede ser una decisión más sencilla.

Usa identidad estable, operaciones puras y evita requestUpdate como parche habitual para mutaciones. El error que más veremos es este: push seguido de ninguna actualización, mutar objetos compartidos o usar índice como identidad duradera.

El siguiente paso ya no es copiar. Construye un tablero de tareas que siempre se actualiza, explica por qué funciona y busca un caso límite antes de enviar tu respuesta.
