Elige binding de texto, atributo, booleano, propiedad o evento según el contrato del destino. En esta clase construiremos un resumen de pedido con bindings correctos; la meta no es memorizar una API, sino poder predecir el contrato antes de escribir código.

Cada expresión tiene un enchufe distinto: texto llena contenido, .propiedad entrega datos ricos, ?booleano controla presencia, @evento conecta comportamiento.

Vamos a leer el código de un resumen de pedido con bindings correctos como un flujo. Nombra la entrada, quién posee el estado, qué dispara el cambio y qué evidencia aparece en pantalla.

Elige el binding por la API del nodo receptor, no por cómo luce el valor en JavaScript. Si el problema no necesita esa frontera, una función o HTML normal puede ser una decisión más sencilla.

Deja que Lit escape texto, evita unsafeHTML con datos externos y mantén cálculos complejos fuera del template. El error que más veremos es este: usar atributo para objetos, escribir disabled="false", interpolar listeners como texto o construir HTML con strings no confiables.

Construye un resumen de pedido con bindings correctos sin perseguir líneas exactas. Cualquier solución que cumpla el contrato, los casos límite y la interacción observable es válida.
