Combina contenido proyectado, variables de valor y parts estructurales sin exponer toda la implementación. En esta clase construiremos un panel de aplicación personalizable; la meta no es memorizar una API, sino poder predecir el contrato antes de escribir código.

Variables ajustan perillas, parts permiten pintar una pieza y slots dejan traer contenido; cada puerta tiene un alcance diferente.

No leas el ejemplo como una receta. Pausa en cada paso de un panel de aplicación personalizable y predice qué observará el navegador antes de continuar.

Usa slots para DOM aportado, custom properties para valores y parts para personalización estructural excepcional. Si el problema no necesita esa frontera, una función o HTML normal puede ser una decisión más sencilla.

Expón pocos nombres semánticos, documenta su estabilidad y evita que el consumidor reconstruya internals. El error que más veremos es este: parts para cada nodo, ::slotted profundo que no funciona o cambiar nombres públicos como refactor interno.

Te toca tomar las decisiones en un panel de aplicación personalizable. El starter prepara el escenario, pero la regla central sigue abierta; usa la vista previa como evidencia.
