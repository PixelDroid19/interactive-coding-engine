Reconstruye la vista desde estado y evita parches DOM que dejan datos e interfaz en desacuerdo. En esta clase construiremos una lista de compras con una sola fuente de verdad; la meta no es memorizar una API, sino poder predecir el contrato antes de escribir código.

El estado es la receta y el DOM es el plato. Si cambias el plato sin cambiar la receta, ya no puedes reconstruirlo.

Vamos con una aplicación distinta antes del reto. En una lista de compras con una sola fuente de verdad, sigue la entrada, el cambio y la salida; después señala dónde aparecen Estado y Render.

Usa render desde estado cuando varias acciones pueden cambiar la misma vista y necesitas resultados repetibles. Si el problema no necesita esa frontera, una función o HTML normal puede ser una decisión más sencilla.

Guarda datos mínimos, produce referencias nuevas y mantén render sin efectos externos. El error que más veremos es este: duplicar estado en el DOM, mezclar mutaciones con parches o guardar nodos derivados como fuente principal.

Ahora cambia el contexto: construye una lista de compras con una sola fuente de verdad. Empieza por el contrato observable, resuelve una decisión cada vez y prueba una variante antes de Comprobar.
