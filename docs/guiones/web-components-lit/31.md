Prepara componentes para trabajo real: pruebas en navegador, documentación, exportaciones, accesibilidad y build de producción. En esta clase construiremos una biblioteca de componentes con contrato verificable; la meta no es memorizar una API, sino poder predecir el contrato antes de escribir código.

Producción es mantener una promesa: API, semántica, pruebas, versión y artefacto deben contar la misma historia a otro equipo.

Este ejemplo no es el ejercicio disfrazado. una biblioteca de componentes con contrato verificable nos permitirá observar el mismo principio en un problema diferente y comparar decisiones.

Empaqueta cuando varios proyectos o equipos consumen el componente; una app única puede conservar módulos internos. Si el problema no necesita esa frontera, una función o HTML normal puede ser una decisión más sencilla.

Prueba en navegador, documenta propiedades/eventos/slots/parts, usa semver y publica artefactos sin fuentes accidentales. El error que más veremos es este: tests DOM simulados, exports ambiguos, breaking changes sin versión, CSS hooks sin documentar o bundle duplicando Lit.

Resuelve una biblioteca de componentes con contrato verificable desde la API pública hacia dentro. El código inicial conserva contexto, no la respuesta; deja que las comprobaciones guíen tu diagnóstico.
