Ubica cálculos antes del render y efectos posteriores según el ciclo de actualización de Lit. En esta clase construiremos un comparador de filtros que calcula una sola vez; la meta no es memorizar una API, sino poder predecir el contrato antes de escribir código.

El ciclo es una cadena: setter programa, willUpdate prepara, render describe, update escribe y updated observa el DOM ya cambiado.

Este ejemplo no es el ejercicio disfrazado. un comparador de filtros que calcula una sola vez nos permitirá observar el mismo principio en un problema diferente y comparar decisiones.

Usa willUpdate para derivados costosos compartidos por render; usa getters para derivados baratos y puros. Si el problema no necesita esa frontera, una función o HTML normal puede ser una decisión más sencilla.

Mira changedProperties, evita efectos externos antes del render y no cambies sin condición la propiedad que disparó el ciclo. El error que más veremos es este: crear bucles en updated, medir DOM antes de actualizar o almacenar cada valor derivable.

Resuelve un comparador de filtros que calcula una sola vez desde la API pública hacia dentro. El código inicial conserva contexto, no la respuesta; deja que las comprobaciones guíen tu diagnóstico.
