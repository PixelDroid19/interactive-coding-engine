Construye una capacidad API completa con contrato de servicio, estados explícitos, transformación de datos y decisiones curatoriales. En esta clase construiremos una sala de museo consultable con servicio, filtros y favoritos; la meta no es memorizar una API, sino poder predecir el contrato antes de escribir código.

Una interfaz API no es una lista bonita: es una máquina de estados alrededor de un contrato propio. Curar implica decidir qué dato importa y qué hacer cuando falta.

Fíjate en la frontera, no solo en la sintaxis. Mientras construimos una sala de museo consultable con servicio, filtros y favoritos, separa responsabilidades de plataforma, componente y consumidor.

Aplica este corte a cualquier vista remota con búsqueda y acciones locales; reduce complejidad en demos estáticas sin red. Si el problema no necesita esa frontera, una función o HTML normal puede ser una decisión más sencilla.

Inyecta cliente, cancela búsquedas, normaliza opcionales, ofrece vacíos útiles, conserva identidad y prueba con fixtures deterministas. El error que más veremos es este: renderizar respuestas crudas, asumir imágenes, confundir cero resultados con error, fetch en render o favoritos por índice.

Lleva el modelo a una sala de museo consultable con servicio, filtros y favoritos. Si te atascas, vuelve al flujo de cuatro pasos; las pistas orientan la investigación, pero no entregan el programa.
