Distingue propiedades públicas de estado interno reactivo y evita convertir cada detalle en API. En esta clase construiremos un contador de inventario con entradas y detalles separados; la meta no es memorizar una API, sino poder predecir el contrato antes de escribir código.

La API pública es el tablero que usa el conductor; el estado interno es el mecanismo bajo el capó. Ambos reaccionan, pero solo uno se promete al consumidor.

La demostración cambia de contexto a propósito. Recorre un contador de inventario con entradas y detalles separados desde su contrato público hasta el DOM y pregunta qué sabe cada pieza.

Usa estado interno para interacción, caché visual y datos derivados que el consumidor no debe configurar. Si el problema no necesita esa frontera, una función o HTML normal puede ser una decisión más sencilla.

Minimiza API, marca estado con state:true y evita reflejar nombres internos. El error que más veremos es este: publicar todo, guardar datos derivados duplicados o permitir que el componente sobrescriba entradas sin avisar.

Cierra la explicación y trabaja desde el comportamiento esperado. Para completar un contador de inventario con entradas y detalles separados, predice, implementa y comprueba más de una entrada.
