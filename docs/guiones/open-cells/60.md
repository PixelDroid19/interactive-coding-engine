Error recuperable. Un error útil explica qué falló, conserva contexto seguro y ofrece una acción posible como reintentar. Hoy seguiremos el recorrido app/data/academy-product-data-manager.js → app/pages/academy-home-page/academy-home-page.js → test/unit/app.test.js → package.json. Para entender Error recuperable, identificaremos quién posee cada dato, quién consume su salida y qué resultado observable confirma el contrato.

Empezamos por app/data/academy-product-data-manager.js. Este archivo posee petición, estados, carreras y cancelación. Antes de tocarlo en Error recuperable, localiza su salida pública y predice quién dependerá de ella.

Vamos a completar app/data/academy-product-data-manager.js. RequestId identifica la petición vigente, AbortController permite cancelarla y emit diferencia loading, success, empty y error. Después lo contrastaremos con app/pages/academy-home-page/academy-home-page.js para verificar el contrato desde otro archivo.

Seguimos en app/pages/academy-home-page/academy-home-page.js. Este archivo coordina componentes, ciclo de página y navegación. Revisa qué recibe de app/data/academy-product-data-manager.js y qué deja preparado para test/unit/app.test.js. app/pages/academy-home-page/academy-home-page.js actúa como consumidor del cambio y no necesita otra edición en este paso.

El siguiente enlace aparece en test/unit/app.test.js. Este archivo comprueba la historia vertical desde rutas y páginas hasta datos. Revisa qué recibe de app/pages/academy-home-page/academy-home-page.js y qué deja preparado para package.json. Solo inspeccionamos test/unit/app.test.js; cambiarlo también ocultaría la causa del resultado.

Terminamos en package.json. Este archivo declara identidad, entradas, dependencias y comandos que consumen las herramientas. Compáralo con test/unit/app.test.js: deben colaborar sin duplicar responsabilidades. En Error recuperable, package.json queda intacto para comprobar el contrato desde fuera.

Ejecutamos el proyecto y buscamos una señal concreta: Retry crea una petición nueva, limpia el error anterior y no duplica suscripciones. Si el preview contradice tu predicción sobre Error recuperable, vuelve al último archivo editado y sigue su salida hasta el consumidor.

Antes del ejercicio, intenta explicar este fallo: Capturar y no emitir el error produce un spinner eterno; fuerza un rechazo y sigue la transición completa. En Error recuperable, propón una causa, cambia una sola frontera y usa el preview o las pruebas para refutarla.
