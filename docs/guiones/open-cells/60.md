Error recuperable. Un error útil explica qué falló, conserva contexto seguro y ofrece una acción posible como reintentar.

En Error recuperable, este archivo es la frontera que vamos a observar. No trabaja solo: Retry crea una petición nueva, limpia el error anterior y no duplica suscripciones.

Acepta datos únicamente cuando pertenecen a la solicitud vigente. Una respuesta antigua debe quedar sin publicar. Primero aislamos esa decisión en aceptarRespuesta60; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: petición → estado → respuesta vigente o descarte → cleanup. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. Capturar y no emitir el error produce un spinner eterno; fuerza un rechazo y sigue la transición completa.

Te devuelvo el punto de partida de Error recuperable. Predice las tres comprobaciones de aceptarRespuesta60 antes de escribir y corrige una sola causa cada vez.

Después del reto de Error recuperable, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
