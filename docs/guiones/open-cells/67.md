Paridad entre browser y CLI. La plataforma no necesita ejecutar Node para conservar contratos de archivos, comandos y resultados compatibles.

Abrimos package.json. Este archivo declara identidad, entradas, dependencias y comandos que consumen las herramientas. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos package.json: type module permite usar import y export. exports señala la entrada pública; cells.entry señala el bootstrap de una app. Los scripts nombran operaciones reales de desarrollo, pruebas, locales y build.

Abrimos app/config/prod.js. Este archivo declara una entrega reproducible sin opciones de depuración. Observa su entrada y busca qué otro archivo lo consume.

Abrimos app/scripts/app.js. Este archivo arranca una única instancia del runtime con outlet, rutas e inicio. Observa su entrada y busca qué otro archivo lo consume.

Abrimos README.md. Este archivo explica cómo consumir, probar y continuar el proyecto fuera del curso. Observa su entrada y busca qué otro archivo lo consume.

Ejecutamos el proyecto después de conectar sus archivos. La evidencia que buscamos es esta: Fixtures compartidas producen el mismo scaffold esperado y cada diferencia se clasifica como soportada o bloqueante.

Antes de practicar, contrasta el resultado con este error frecuente: Comparar solo nombres de archivo omite semántica; valida imports, scripts, API, demo, tests y metadata.
