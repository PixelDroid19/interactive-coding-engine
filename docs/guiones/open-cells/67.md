Paridad entre browser y CLI. La plataforma no necesita ejecutar Node para conservar contratos de archivos, comandos y resultados compatibles.

En Paridad entre browser y CLI, este archivo es la frontera que vamos a observar. No trabaja solo: Fixtures compartidas producen el mismo scaffold esperado y cada diferencia se clasifica como soportada o bloqueante.

Valida una entrega completa: ZIP estándar, pruebas, build y ausencia de secretos. Un archivo descargado por sí solo no basta. Primero aislamos esa decisión en validarEntrega67; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: workspace limpio → test y build → ZIP → continuación con CLI. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. Comparar solo nombres de archivo omite semántica; valida imports, scripts, API, demo, tests y metadata.

Te devuelvo el punto de partida de Paridad entre browser y CLI. Predice las tres comprobaciones de validarEntrega67 antes de escribir y corrige una sola causa cada vez.

Después del reto de Paridad entre browser y CLI, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
