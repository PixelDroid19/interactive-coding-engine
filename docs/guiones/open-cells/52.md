Payloads estables. El payload de canal es una API entre partes que pueden evolucionar por separado. Hoy seguiremos el recorrido app/scripts/channels.js → app/pages/academy-home-page/academy-home-page.js → app/pages/academy-product-detail-page/academy-product-detail-page.js → package.json. Para entender Payloads estables, identificaremos quién posee cada dato, quién consume su salida y qué resultado observable confirma el contrato.

Nuestro punto de partida es app/scripts/channels.js. Este archivo nombra contratos de comunicación de larga distancia. Antes de tocarlo en Payloads estables, localiza su salida pública y predice quién dependerá de ella. app/scripts/channels.js actúa como consumidor del cambio y no necesita otra edición en este paso.

Seguimos en app/pages/academy-home-page/academy-home-page.js. Este archivo coordina componentes, ciclo de página y navegación. Revisa qué recibe de app/scripts/channels.js y qué deja preparado para app/pages/academy-product-detail-page/academy-product-detail-page.js.

Ahora sí editamos app/pages/academy-home-page/academy-home-page.js. Después lo contrastaremos con app/pages/academy-product-detail-page/academy-product-detail-page.js para verificar el contrato desde otro archivo.

La última parada es package.json. Este archivo declara identidad, entradas, dependencias y comandos que consumen las herramientas. Compáralo con app/pages/academy-product-detail-page/academy-product-detail-page.js: deben colaborar sin duplicar responsabilidades. package.json actúa como consumidor del cambio y no necesita otra edición en este paso.

Ya está conectado el recorrido. La comprobación importante es esta: Contiene datos serializables, versión o forma documentada y evita instancias privadas. Si el preview contradice tu predicción sobre Payloads estables, vuelve al último archivo editado y sigue su salida hasta el consumidor.

Ahora piensa en el caso que suele romper este contrato: Enviar un elemento DOM permite mutaciones invisibles; copia los valores de negocio que realmente necesita el receptor. En Payloads estables, propón una causa, cambia una sola frontera y usa el preview o las pruebas para refutarla.
