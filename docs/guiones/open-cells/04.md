Comandos reales en un navegador. El parser acepta cells component:create, component:test, component:locales, component:documentation, component:build:demo y component:dev. Las opciones desconocidas, instalación de dependencias, puertos y watch se rechazan con un mensaje comprensible.

En Comandos reales en un navegador, este archivo es la frontera que vamos a observar. No trabaja solo: Cada operación lleva requestId, sessionId y generation. El identificador permite asociar respuesta y petición; la sesión evita mezclar laboratorios; la generación impide que un resultado viejo reemplace el proyecto más reciente.

Completa el mapa de responsabilidades. Debe distinguir componente, página, aplicación y runtime educativo sin usar una respuesta fija. Primero aislamos esa decisión en identificarFrontera04; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: responsabilidad → frontera propietaria → salida observable. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. Cancelar no equivale a marcar una tarea como exitosa. El cliente rechaza la operación pendiente y el Worker recibe la orden. Los errores conservan código, archivo, línea, columna y una pista cuando esa información existe.

Te devuelvo el punto de partida de Comandos reales en un navegador. Predice las tres comprobaciones de identificarFrontera04 antes de escribir y corrige una sola causa cada vez.

Después del reto de Comandos reales en un navegador, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
