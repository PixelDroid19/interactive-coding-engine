Comandos reales en un navegador. Distingue intención de comando, capacidad disponible y resultado verificable sin fingir una terminal de sistema.

Abrimos package.json. Este archivo declara identidad, entradas, dependencias y comandos que consumen las herramientas. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos package.json: type module permite usar import y export. exports señala la entrada pública; cells.entry señala el bootstrap de una app. Los scripts nombran operaciones reales de desarrollo, pruebas, locales y build.

Abrimos demo/index.html. Este archivo presenta controles y una instancia real del paquete. Observa su entrada y busca qué otro archivo lo consume.

Abrimos demo/demo.js. Este archivo consume la entrada pública y conecta propiedades, idioma y eventos. Observa su entrada y busca qué otro archivo lo consume.

Abrimos demo/demo-build.js. Este archivo actúa como raíz del grafo que construye la demo. Observa su entrada y busca qué otro archivo lo consume.

Ejecutamos el proyecto después de conectar sus archivos. La evidencia que buscamos es esta: Cada operación lleva requestId, sessionId y generation. El identificador permite asociar respuesta y petición; la sesión evita mezclar laboratorios; la generación impide que un resultado viejo reemplace el proyecto más reciente.

Antes de practicar, contrasta el resultado con este error frecuente: Cancelar no equivale a marcar una tarea como exitosa. El cliente rechaza la operación pendiente y el Worker recibe la orden. Los errores conservan código, archivo, línea, columna y una pista cuando esa información existe.

La lectura siguiente abre un laboratorio de proyecto para Comandos reales en un navegador. Allí corregirás archivos reales, construirás la vista previa y ejecutarás contratos sin recibir una solución copiada.
