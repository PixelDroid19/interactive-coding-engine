disabled como contrato observable. disabled no es solo un color gris: bloquea interacción, comunica semántica accesible y evita emitir acciones.

En disabled como contrato observable, este archivo es la frontera que vamos a observar. No trabaja solo: Propiedad, atributo, control interno y evento mantienen el mismo estado; teclado y puntero observan el mismo bloqueo.

Haz que el contrato visible respete disabled y conserve loading, empty, error o success. Una entrada desconocida debe producir un estado seguro. Primero aislamos esa decisión en estadoVisible11; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: propiedad pública → estado interno → render e interacción. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. Cambiar únicamente CSS deja activo el comportamiento; intenta activar por teclado y escucha si todavía sale el evento.

Te devuelvo el punto de partida de disabled como contrato observable. Predice las tres comprobaciones de estadoVisible11 antes de escribir y corrige una sola causa cada vez.

Después del reto de disabled como contrato observable, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
