Bootstrap del runtime público. El bootstrap recibe outlet, rutas e inicio; su trabajo es coordinar, no definir contenido de cada página.

Abrimos index.html. Este archivo crea la raíz que el runtime montará en el navegador. Observa su entrada y busca qué otro archivo lo consume.

Abrimos app/scripts/app.js. Este archivo arranca una única instancia del runtime con outlet, rutas e inicio. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos app/scripts/app.js: importamos startApp y ROUTES. mainNode coincide con el outlet HTML, initialTemplate coincide con el name de una ruta y el bootstrap ocurre una sola vez.

Abrimos app/scripts/app-routes.js. Este archivo relaciona URL, nombre estable, tag de página y carga lazy. Observa su entrada y busca qué otro archivo lo consume.

Abrimos app/pages/academy-home-page/academy-home-page.js. Este archivo coordina componentes, ciclo de página y navegación. Observa su entrada y busca qué otro archivo lo consume.

Ejecutamos el proyecto después de conectar sus archivos. La evidencia que buscamos es esta: Arranca una vez, publica contexto de aplicación y muestra un error observable si falta raíz o ruta inicial.

Antes de practicar, contrasta el resultado con este error frecuente: Iniciar el runtime desde varios módulos duplica listeners y navegación; localiza una única entrada.

La lectura siguiente abre un laboratorio de proyecto para Bootstrap del runtime público. Allí corregirás archivos reales, construirás la vista previa y ejecutarás contratos sin recibir una solución copiada.
