Bootstrap del runtime público. El bootstrap recibe outlet, rutas e inicio; su trabajo es coordinar, no definir contenido de cada página.

En Bootstrap del runtime público, este archivo es la frontera que vamos a observar. No trabaja solo: Arranca una vez, publica contexto de aplicación y muestra un error observable si falta raíz o ruta inicial.

Devuelve la ruta cuyo name coincide con la intención recibida. No uses el path como sustituto ni elijas siempre la primera ruta. Primero aislamos esa decisión en resolverRuta42; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: ruta → página activa → entrada y cleanup. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. Iniciar el runtime desde varios módulos duplica listeners y navegación; localiza una única entrada.

Te devuelvo el punto de partida de Bootstrap del runtime público. Predice las tres comprobaciones de resolverRuta42 antes de escribir y corrige una sola causa cada vez.

Después del reto de Bootstrap del runtime público, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
