Por qué registrar dependencias localmente. Un host debe poder decidir qué clase implementa una etiqueta dentro de su árbol sin contaminar toda la página.

En Por qué registrar dependencias localmente, este archivo es la frontera que vamos a observar. No trabaja solo: Las dependencias del template aparecen en scopedElements y no requieren customElements.define global desde el host.

Resuelve la clase asociada al tag recibido. No fijes un componente concreto ni registres nada globalmente. Primero aislamos esa decisión en resolverScoped15; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: tag local → registro del host → clase importada. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. Registrar todo globalmente funciona hasta que dos versiones compiten; prueba dos hosts con la misma etiqueta y clases distintas.

Te devuelvo el punto de partida de Por qué registrar dependencias localmente. Predice las tres comprobaciones de resolverScoped15 antes de escribir y corrige una sola causa cada vez.

Después del reto de Por qué registrar dependencias localmente, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
