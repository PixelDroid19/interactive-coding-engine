Workspace virtual y exportación. Todas las rutas se normalizan con barras, rechazan rutas absolutas y no pueden escapar mediante segmentos .. . También se detectan colisiones donde una ruta intenta ser archivo y directorio al mismo tiempo.

En Workspace virtual y exportación, este archivo es la frontera que vamos a observar. No trabaja solo: Cada escritura produce un snapshot nuevo y aumenta la generación. Esto permite descartar respuestas atrasadas, persistir estados coherentes y comparar el trabajo del estudiante sin perder el proyecto anterior.

Completa el mapa de responsabilidades. Debe distinguir componente, página, aplicación y runtime educativo sin usar una respuesta fija. Primero aislamos esa decisión en identificarFrontera05; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: responsabilidad → frontera propietaria → salida observable. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. La exportación escribe entradas ZIP reales con CRC y conserva la jerarquía completa. package.json usa comandos Cells, de modo que el estudiante puede descomprimir el proyecto y continuar con el toolchain fuera de la plataforma. Un error frecuente consiste en cambiar varias fronteras a la vez; conserva una predicción y comprueba una sola causa antes de continuar.

Te devuelvo el punto de partida de Workspace virtual y exportación. Predice las tres comprobaciones de identificarFrontera05 antes de escribir y corrige una sola causa cada vez.

Después del reto de Workspace virtual y exportación, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
