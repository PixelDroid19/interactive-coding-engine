Build con configuración de producción. El build de producción fija entorno, resuelve rutas y elimina capacidades de depuración sin cambiar comportamiento público.

Abrimos test/unit/app.test.js. Este archivo comprueba la historia vertical desde rutas y páginas hasta datos. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos test/unit/app.test.js: las pruebas conectan rutas, páginas y data manager con valores variables; además verifican cleanup y respuestas antiguas.

Abrimos app/data/academy-product-data-manager.js. Este archivo posee petición, estados, carreras y cancelación. Observa su entrada y busca qué otro archivo lo consume.

Abrimos app/scripts/app-routes.js. Este archivo relaciona URL, nombre estable, tag de página y carga lazy. Observa su entrada y busca qué otro archivo lo consume.

Abrimos package.json. Este archivo declara identidad, entradas, dependencias y comandos que consumen las herramientas. Observa su entrada y busca qué otro archivo lo consume.

Ejecutamos el proyecto después de conectar sus archivos. La evidencia que buscamos es esta: El artefacto arranca desde cero, carga páginas lazy y no contiene secretos ni URLs de desarrollo.

Antes de practicar, contrasta el resultado con este error frecuente: Un build exitoso puede estar mal configurado; inspecciona el artefacto y ejecuta un smoke real.

La lectura siguiente abre un laboratorio de proyecto para Build con configuración de producción. Allí corregirás archivos reales, construirás la vista previa y ejecutarás contratos sin recibir una solución copiada.
