Workspace real de aplicación. El workspace es un proyecto exportable y versionado, no una colección de snippets sin relación. Hoy seguiremos el recorrido app/pages/academy-home-page/academy-home-page.js → index.html → app/scripts/app.js → app/scripts/app-routes.js → app/config/prod.js. Para entender Workspace real de aplicación, identificaremos quién posee cada dato, quién consume su salida y qué resultado observable confirma el contrato.

Nuestro punto de partida es app/pages/academy-home-page/academy-home-page.js. Este archivo coordina componentes, ciclo de página y navegación. Antes de tocarlo en Workspace real de aplicación, localiza su salida pública y predice quién dependerá de ella.

Vamos a completar app/pages/academy-home-page/academy-home-page.js. PageMixin aporta navegación y canales; ScopedElementsMixin resuelve la tarjeta. onPageEnter adquiere recursos, onPageLeave los libera y render conserva UI declarativa. Después lo contrastaremos con index.html para verificar el contrato desde otro archivo.

Seguimos en index.html. Este archivo crea la raíz que el runtime montará en el navegador. Revisa qué recibe de app/pages/academy-home-page/academy-home-page.js y qué deja preparado para app/scripts/app.js. Solo inspeccionamos index.html; cambiarlo también ocultaría la causa del resultado.

El siguiente enlace aparece en app/scripts/app.js. Este archivo arranca una única instancia del runtime con outlet, rutas e inicio. Revisa qué recibe de index.html y qué deja preparado para app/scripts/app-routes.js. En Workspace real de aplicación, app/scripts/app.js queda intacto para comprobar el contrato desde fuera.

Ahora pasamos a app/scripts/app-routes.js. Este archivo relaciona URL, nombre estable, tag de página y carga lazy. Revisa qué recibe de app/scripts/app.js y qué deja preparado para app/config/prod.js. app/scripts/app-routes.js actúa como consumidor del cambio y no necesita otra edición en este paso.

Cerramos el recorrido en app/config/prod.js. Este archivo declara una entrega reproducible sin opciones de depuración. Compáralo con app/scripts/app-routes.js: deben colaborar sin duplicar responsabilidades. Solo inspeccionamos app/config/prod.js; cambiarlo también ocultaría la causa del resultado.

Ya está conectado el recorrido. La comprobación importante es esta: La entrada, rutas y páginas forman un grafo resoluble; dev y prod conservan configuración explícita. Si el preview contradice tu predicción sobre Workspace real de aplicación, vuelve al último archivo editado y sigue su salida hasta el consumidor.

Ahora piensa en el caso que suele romper este contrato: Guardar solo el archivo activo produce un ZIP incompleto; valida el snapshot entero antes de construir. En Workspace real de aplicación, propón una causa, cambia una sola frontera y usa el preview o las pruebas para refutarla.

A continuación podrás repasar el modelo con calma sobre Workspace real de aplicación. Después, el proyecto de Workspace real de aplicación se abrirá completo para que experimentes y compares soluciones equivalentes sin recibir una línea para copiar.
