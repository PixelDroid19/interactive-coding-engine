Comunicación padre e hijo. El padre entrega datos mediante propiedades y el hijo devuelve intenciones mediante eventos; ninguno invade métodos privados del otro.

En Comunicación padre e hijo, este archivo es la frontera que vamos a observar. No trabaja solo: El flujo se puede dibujar como entrada descendente y evento ascendente sin referencias ocultas.

Busca la clave en el idioma solicitado y sustituye los placeholders recibidos. Una clave ausente debe seguir siendo visible como ausencia. Primero aislamos esa decisión en crearMensaje30; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: clave y valores → texto localizado; acción → evento público. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. El padre que consulta shadowRoot para corregir al hijo depende de su implementación; prueba el mismo contrato con otro hijo.

Te devuelvo el punto de partida de Comunicación padre e hijo. Predice las tres comprobaciones de crearMensaje30 antes de escribir y corrige una sola causa cada vez.

Después del reto de Comunicación padre e hijo, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
