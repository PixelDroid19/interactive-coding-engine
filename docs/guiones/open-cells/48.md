Navegación imperativa. navigate expresa una intención desde una página o Bridge; no debe filtrarse hacia componentes puramente visuales. Hoy seguiremos el recorrido app/components/academy-product-card/academy-product-card.js → app/pages/academy-home-page/academy-home-page.js → app/scripts/app-routes.js → package.json. Para entender Navegación imperativa, identificaremos quién posee cada dato, quién consume su salida y qué resultado observable confirma el contrato.

Empezamos por app/components/academy-product-card/academy-product-card.js. Este archivo encapsula presentación y devuelve una intención mediante evento. Antes de tocarlo en Navegación imperativa, localiza su salida pública y predice quién dependerá de ella. En Navegación imperativa, app/components/academy-product-card/academy-product-card.js queda intacto para comprobar el contrato desde fuera.

Seguimos en app/pages/academy-home-page/academy-home-page.js. Este archivo coordina componentes, ciclo de página y navegación. Revisa qué recibe de app/components/academy-product-card/academy-product-card.js y qué deja preparado para app/scripts/app-routes.js. app/pages/academy-home-page/academy-home-page.js actúa como consumidor del cambio y no necesita otra edición en este paso.

El siguiente enlace aparece en app/scripts/app-routes.js. Este archivo relaciona URL, nombre estable, tag de página y carga lazy. Revisa qué recibe de app/pages/academy-home-page/academy-home-page.js y qué deja preparado para package.json.

Este es el archivo que modificaremos: app/scripts/app-routes.js. Cada objeto separa path de URL, name estable, component que se monta y action que importa la página solo cuando se visita. Después lo contrastaremos con package.json para verificar el contrato desde otro archivo.

Terminamos en package.json. Este archivo declara identidad, entradas, dependencias y comandos que consumen las herramientas. Compáralo con app/scripts/app-routes.js: deben colaborar sin duplicar responsabilidades. En Navegación imperativa, package.json queda intacto para comprobar el contrato desde fuera.

Ejecutamos el proyecto y buscamos una señal concreta: La página traduce el evento del hijo a navigate con un nombre conocido y parámetros explícitos. Si el preview contradice tu predicción sobre Navegación imperativa, vuelve al último archivo editado y sigue su salida hasta el consumidor.

Antes del ejercicio, intenta explicar este fallo: Una tarjeta que importa el router deja de ser reutilizable; muévela a otra página y comprueba que aún funciona. En Navegación imperativa, propón una causa, cambia una sola frontera y usa el preview o las pruebas para refutarla.
