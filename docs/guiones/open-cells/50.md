Evento, canal o navegación. Evento comunica dentro de un árbol cercano; canal desacopla participantes de aplicación; navegación cambia página.

Abrimos app/components/academy-product-card/academy-product-card.js. Este archivo encapsula presentación y devuelve una intención mediante evento. Observa su entrada y busca qué otro archivo lo consume.

Abrimos app/pages/academy-home-page/academy-home-page.js. Este archivo coordina componentes, ciclo de página y navegación. Observa su entrada y busca qué otro archivo lo consume.

Abrimos app/scripts/channels.js. Este archivo nombra contratos de comunicación de larga distancia. Observa su entrada y busca qué otro archivo lo consume.

Abrimos app/scripts/app-routes.js. Este archivo relaciona URL, nombre estable, tag de página y carga lazy. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos app/scripts/app-routes.js: cada objeto separa path de URL, name estable, component que se monta y action que importa la página solo cuando se visita.

Ejecutamos el proyecto después de conectar sus archivos. La evidencia que buscamos es esta: La elección se justifica por distancia, duración y propietario del dato, no por comodidad de sintaxis.

Antes de practicar, contrasta el resultado con este error frecuente: Publicar cada click en un canal global crea tráfico sin significado; nombra la decisión y limita su alcance.

La lectura siguiente abre un laboratorio de proyecto para Evento, canal o navegación. Allí corregirás archivos reales, construirás la vista previa y ejecutarás contratos sin recibir una solución copiada.
