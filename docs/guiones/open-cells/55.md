Bridge entre la aplicación web y el shell nativo. Bridge separa las páginas Cells del contenedor móvil: el shell puede comunicar ciclo de vida, sesión o capacidades, pero los componentes reciben contratos web serializables. Hoy seguiremos el recorrido app/bridge/native-adapter.js → app/scripts/channels.js → app/pages/academy-home-page/academy-home-page.js → app/scripts/app-routes.js. Para entender Bridge entre la aplicación web y el shell nativo, identificaremos quién posee cada dato, quién consume su salida y qué resultado observable confirma el contrato.

Nuestro punto de partida es app/bridge/native-adapter.js. Este archivo valida mensajes del shell y los traduce a navegación o canales internos. Antes de tocarlo en Bridge entre la aplicación web y el shell nativo, localiza su salida pública y predice quién dependerá de ella. app/bridge/native-adapter.js actúa como consumidor del cambio y no necesita otra edición en este paso.

Después abrimos app/scripts/channels.js. Este archivo nombra contratos de comunicación de larga distancia. Revisa qué recibe de app/bridge/native-adapter.js y qué deja preparado para app/pages/academy-home-page/academy-home-page.js. Solo inspeccionamos app/scripts/channels.js; cambiarlo también ocultaría la causa del resultado.

Seguimos en app/pages/academy-home-page/academy-home-page.js. Este archivo coordina componentes, ciclo de página y navegación. Revisa qué recibe de app/scripts/channels.js y qué deja preparado para app/scripts/app-routes.js.

Ahora sí editamos app/pages/academy-home-page/academy-home-page.js. PageMixin aporta navegación y canales; ScopedElementsMixin resuelve la tarjeta. onPageEnter adquiere recursos, onPageLeave los libera y render conserva UI declarativa. Después lo contrastaremos con app/scripts/app-routes.js para verificar el contrato desde otro archivo.

La última parada es app/scripts/app-routes.js. Este archivo relaciona URL, nombre estable, tag de página y carga lazy. Compáralo con app/pages/academy-home-page/academy-home-page.js: deben colaborar sin duplicar responsabilidades. app/scripts/app-routes.js actúa como consumidor del cambio y no necesita otra edición en este paso.

Ya está conectado el recorrido. La comprobación importante es esta: Un adaptador aislado valida cada mensaje, publica estados internos y mantiene fuera de páginas y componentes cualquier objeto específico de la plataforma nativa. Si el preview contradice tu predicción sobre Bridge entre la aplicación web y el shell nativo, vuelve al último archivo editado y sigue su salida hasta el consumidor.

Ahora piensa en el caso que suele romper este contrato: Llamar APIs nativas desde cada página hace imposible probar o sustituir el shell; dibuja una única frontera y comprueba mensajes válidos, incompletos y desconocidos. En Bridge entre la aplicación web y el shell nativo, propón una causa, cambia una sola frontera y usa el preview o las pruebas para refutarla.
