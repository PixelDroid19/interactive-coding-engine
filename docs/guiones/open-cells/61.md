Cancelación y respuestas fuera de orden. Abortar reduce trabajo, pero un requestId también impide que una respuesta antigua gane si no pudo cancelarse.

En Cancelación y respuestas fuera de orden, este archivo es la frontera que vamos a observar. No trabaja solo: La última solicitud es la única autorizada para publicar success, empty o error.

Acepta datos únicamente cuando pertenecen a la solicitud vigente. Una respuesta antigua debe quedar sin publicar. Primero aislamos esa decisión en aceptarRespuesta61; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: petición → estado → respuesta vigente o descarte → cleanup. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. Probar solo una petición no expone carreras; resuelve dos promesas en orden inverso.

Te devuelvo el punto de partida de Cancelación y respuestas fuera de orden. Predice las tres comprobaciones de aceptarRespuesta61 antes de escribir y corrige una sola causa cada vez.

Después del reto de Cancelación y respuestas fuera de orden, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
