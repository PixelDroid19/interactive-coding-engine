this.t y claves visibles. La interfaz pide significado mediante una clave; el catálogo decide la frase para el idioma activo.

Abrimos locales/locales.json. Este archivo es la fuente de las traducciones del componente. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos locales/locales.json: en y es repiten exactamente las mismas claves. El placeholder de nombre también debe coincidir para que this.t pueda sustituirlo sin casos especiales.

Abrimos src/academy-learning-card.js. Este archivo implementa propiedades, render, dependencias scoped y eventos del componente. Observa su entrada y busca qué otro archivo lo consume.

Abrimos demo/demo.js. Este archivo consume la entrada pública y conecta propiedades, idioma y eventos. Observa su entrada y busca qué otro archivo lo consume.

Abrimos package.json. Este archivo declara identidad, entradas, dependencias y comandos que consumen las herramientas. Observa su entrada y busca qué otro archivo lo consume.

Ejecutamos el proyecto después de conectar sus archivos. La evidencia que buscamos es esta: Todo texto de producto usa claves estables, y una clave ausente se ve como error en vez de desaparecer.

Antes de practicar, contrasta el resultado con este error frecuente: Mezclar texto literal y traducido crea pantallas parcialmente localizadas; busca nodos visibles fuera de this.t.
