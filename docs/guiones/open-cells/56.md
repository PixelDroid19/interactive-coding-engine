Eventos externos y canales. Un adaptador recibe un evento externo, valida su payload y publica una forma interna estable.

En Eventos externos y canales, este archivo es la frontera que vamos a observar. No trabaja solo: La frontera traduce nombres y datos una sola vez y permite sustituir el origen externo.

Acepta datos únicamente cuando pertenecen a la solicitud vigente. Una respuesta antigua debe quedar sin publicar. Primero aislamos esa decisión en aceptarRespuesta56; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: petición → estado → respuesta vigente o descarte → cleanup. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. Reenviar el evento completo acopla la app al proveedor; prueba con un segundo origen equivalente.

Te devuelvo el punto de partida de Eventos externos y canales. Predice las tres comprobaciones de aceptarRespuesta56 antes de escribir y corrige una sola causa cada vez.

Después del reto de Eventos externos y canales, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
