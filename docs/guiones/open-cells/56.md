Deep links, ciclo de vida y eventos externos. Un mensaje externo no es navegación todavía: primero se valida y normaliza; después el adaptador decide si publica un canal o navega por un nombre de ruta.

Abrimos app/bridge/native-adapter.js. Este archivo valida mensajes del shell y los traduce a navegación o canales internos. Observa su entrada y busca qué otro archivo lo consume.

Abrimos app/scripts/app-routes.js. Este archivo relaciona URL, nombre estable, tag de página y carga lazy. Observa su entrada y busca qué otro archivo lo consume.

Abrimos app/pages/academy-home-page/academy-home-page.js. Este archivo coordina componentes, ciclo de página y navegación. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos app/pages/academy-home-page/academy-home-page.js: PageMixin aporta navegación y canales; ScopedElementsMixin resuelve la tarjeta. onPageEnter adquiere recursos, onPageLeave los libera y render conserva UI declarativa.

Abrimos app/scripts/channels.js. Este archivo nombra contratos de comunicación de larga distancia. Observa su entrada y busca qué otro archivo lo consume.

Ejecutamos el proyecto después de conectar sus archivos. La evidencia que buscamos es esta: Deep links entregan route y params; cambios de foreground, background o sesión se convierten en un payload pequeño del canal de ciclo de vida.

Antes de practicar, contrasta el resultado con este error frecuente: Reenviar el objeto externo completo acopla la app al proveedor y puede filtrar datos privados; crea una forma interna explícita y prueba un segundo origen equivalente.
