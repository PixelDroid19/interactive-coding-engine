CellsPageMixin. Una página es un componente enrutable con API de Bridge y ciclo de activación. Hoy seguiremos el recorrido app/scripts/app-routes.js → app/pages/academy-home-page/academy-home-page.js → app/components/academy-product-card/academy-product-card.js → app/pages/academy-home-page/locales/locales.json. Para entender CellsPageMixin, identificaremos quién posee cada dato, quién consume su salida y qué resultado observable confirma el contrato.

Nuestro punto de partida es app/scripts/app-routes.js. Este archivo relaciona URL, nombre estable, tag de página y carga lazy. Antes de tocarlo en CellsPageMixin, localiza su salida pública y predice quién dependerá de ella.

Aquí hacemos el cambio principal en app/scripts/app-routes.js. Cada objeto separa path de URL, name estable, component que se monta y action que importa la página solo cuando se visita. Después lo contrastaremos con app/pages/academy-home-page/academy-home-page.js para verificar el contrato desde otro archivo.

Después abrimos app/pages/academy-home-page/academy-home-page.js. Este archivo coordina componentes, ciclo de página y navegación. Revisa qué recibe de app/scripts/app-routes.js y qué deja preparado para app/components/academy-product-card/academy-product-card.js.

Vamos a completar app/pages/academy-home-page/academy-home-page.js. PageMixin aporta navegación y canales; ScopedElementsMixin resuelve la tarjeta. onPageEnter adquiere recursos, onPageLeave los libera y render conserva UI declarativa. Después lo contrastaremos con app/components/academy-product-card/academy-product-card.js para verificar el contrato desde otro archivo.

Seguimos en app/components/academy-product-card/academy-product-card.js. Este archivo encapsula presentación y devuelve una intención mediante evento. Revisa qué recibe de app/pages/academy-home-page/academy-home-page.js y qué deja preparado para app/pages/academy-home-page/locales/locales.json.

Ahora sí editamos app/components/academy-product-card/academy-product-card.js. La tarjeta recibe product por propiedad y emite select. No importa rutas ni canales porque esa coordinación pertenece a la página. Después lo contrastaremos con app/pages/academy-home-page/locales/locales.json para verificar el contrato desde otro archivo.

La última parada es app/pages/academy-home-page/locales/locales.json. Este archivo conserva textos que pertenecen únicamente a la página inicial. Compáralo con app/components/academy-product-card/academy-product-card.js: deben colaborar sin duplicar responsabilidades. app/pages/academy-home-page/locales/locales.json actúa como consumidor del cambio y no necesita otra edición en este paso.

Ya está conectado el recorrido. La comprobación importante es esta: Su tag y clase terminan en -page, aplica CellsPageMixin y mantiene renderizado declarativo. Si el preview contradice tu predicción sobre CellsPageMixin, vuelve al último archivo editado y sigue su salida hasta el consumidor.

Ahora piensa en el caso que suele romper este contrato: Usar el mixin en cada componente borra fronteras; resérvalo para superficies que participan en rutas y canales de app. En CellsPageMixin, propón una causa, cambia una sola frontera y usa el preview o las pruebas para refutarla.

A continuación podrás repasar el modelo con calma sobre CellsPageMixin. Después, el proyecto de CellsPageMixin se abrirá completo para que experimentes y compares soluciones equivalentes sin recibir una línea para copiar.
