CellsPageMixin. Una página es un componente enrutable con API de Bridge y ciclo de activación.

Abrimos app/scripts/app-routes.js. Este archivo relaciona URL, nombre estable, tag de página y carga lazy. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos app/scripts/app-routes.js: cada objeto separa path de URL, name estable, component que se monta y action que importa la página solo cuando se visita.

Abrimos app/pages/academy-home-page/academy-home-page.js. Este archivo coordina componentes, ciclo de página y navegación. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos app/pages/academy-home-page/academy-home-page.js: PageMixin aporta navegación y canales; ScopedElementsMixin resuelve la tarjeta. onPageEnter adquiere recursos, onPageLeave los libera y render conserva UI declarativa.

Abrimos app/components/academy-product-card/academy-product-card.js. Este archivo encapsula presentación y devuelve una intención mediante evento. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos app/components/academy-product-card/academy-product-card.js: la tarjeta recibe product por propiedad y emite select. No importa rutas ni canales porque esa coordinación pertenece a la página.

Abrimos app/pages/academy-home-page/locales/locales.json. Este archivo conserva textos que pertenecen únicamente a la página inicial. Observa su entrada y busca qué otro archivo lo consume.

Ejecutamos el proyecto después de conectar sus archivos. La evidencia que buscamos es esta: Su tag y clase terminan en -page, aplica CellsPageMixin y mantiene renderizado declarativo.

Antes de practicar, contrasta el resultado con este error frecuente: Usar el mixin en cada componente borra fronteras; resérvalo para superficies que participan en rutas y canales de app.
