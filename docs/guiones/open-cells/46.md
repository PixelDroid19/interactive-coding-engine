onPageLeave y cleanup. Salir de una página transfiere propiedad: aborta peticiones y elimina suscripciones antes de que otra página gobierne la pantalla.

En onPageLeave y cleanup, este archivo es la frontera que vamos a observar. No trabaja solo: Después de onPageLeave no llegan actualizaciones de canales ni respuestas de la visita anterior.

Devuelve la ruta cuyo name coincide con la intención recibida. No uses el path como sustituto ni elijas siempre la primera ruta. Primero aislamos esa decisión en resolverRuta46; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: ruta → página activa → entrada y cleanup. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. Ocultar el DOM no detiene trabajo; publica después de salir y comprueba que la página vieja permanece inmóvil.

Te devuelvo el punto de partida de onPageLeave y cleanup. Predice las tres comprobaciones de resolverRuta46 antes de escribir y corrige una sola causa cada vez.

Después del reto de onPageLeave y cleanup, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
