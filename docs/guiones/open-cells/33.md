Aislamiento y timeout de pruebas. Cada prueba necesita un DOM limpio y un límite de tiempo que convierta bloqueos en resultados diagnosticables.

En Aislamiento y timeout de pruebas, este archivo es la frontera que vamos a observar. No trabaja solo: El runner separa casos, restaura recursos y reporta qué promesa o evento no terminó.

Consulta la parte de la API pública solicitada. La comprobación debe aceptar valores distintos y no depender del orden del objeto. Primero aislamos esa decisión en leerApiPublica33; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: entrada pública → consumidor real → evidencia repetible. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. Compartir instancias hace que el orden cambie el resultado; ejecuta el mismo caso solo y después dentro de la suite.

Te devuelvo el punto de partida de Aislamiento y timeout de pruebas. Predice las tres comprobaciones de leerApiPublica33 antes de escribir y corrige una sola causa cada vez.

Después del reto de Aislamiento y timeout de pruebas, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
