Coverage útil por archivo. Coverage señala qué código fue ejecutado; no demuestra por sí solo que el comportamiento sea correcto.

Abrimos test/unit/academy-learning-card.test.js. Este archivo prueba el componente desde su superficie pública. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos test/unit/academy-learning-card.test.js: cada caso crea o usa la API pública, cambia valores, espera la actualización y comprueba DOM, scopedElements o eventos; no busca una línea exacta.

Abrimos src/academy-learning-card.js. Este archivo implementa propiedades, render, dependencias scoped y eventos del componente. Observa su entrada y busca qué otro archivo lo consume.

Abrimos demo/index.html. Este archivo presenta controles y una instancia real del paquete. Observa su entrada y busca qué otro archivo lo consume.

Abrimos academy-learning-card.js. Este archivo registra el tag público que una aplicación puede instanciar. Observa su entrada y busca qué otro archivo lo consume.

Ejecutamos el proyecto después de conectar sus archivos. La evidencia que buscamos es esta: La interfaz diferencia cobertura de líneas y cobertura de contratos públicos, con archivos y denominadores visibles.

Antes de practicar, contrasta el resultado con este error frecuente: Celebrar 100% con aserciones débiles crea falsa seguridad; introduce un defecto y verifica que al menos una prueba falle.

La lectura siguiente abre un laboratorio de proyecto para Coverage útil por archivo. Allí corregirás archivos reales, construirás la vista previa y ejecutarás contratos sin recibir una solución copiada.
