Coverage útil por archivo. Coverage señala qué código fue ejecutado; no demuestra por sí solo que el comportamiento sea correcto. Hoy seguiremos el recorrido test/unit/academy-learning-card.test.js → src/academy-learning-card.js → demo/index.html → academy-learning-card.js. Para entender Coverage útil por archivo, identificaremos quién posee cada dato, quién consume su salida y qué resultado observable confirma el contrato.

Nuestro punto de partida es test/unit/academy-learning-card.test.js. Este archivo prueba el componente desde su superficie pública. Antes de tocarlo en Coverage útil por archivo, localiza su salida pública y predice quién dependerá de ella.

Este es el archivo que modificaremos: test/unit/academy-learning-card.test.js. Cada caso crea o usa la API pública, cambia valores, espera la actualización y comprueba DOM, scopedElements o eventos; no busca una línea exacta. Después lo contrastaremos con src/academy-learning-card.js para verificar el contrato desde otro archivo.

Ahora pasamos a src/academy-learning-card.js. Este archivo implementa propiedades, render, dependencias scoped y eventos del componente. Revisa qué recibe de test/unit/academy-learning-card.test.js y qué deja preparado para demo/index.html. Solo inspeccionamos src/academy-learning-card.js; cambiarlo también ocultaría la causa del resultado.

Después abrimos demo/index.html. Este archivo presenta controles y una instancia real del paquete. Revisa qué recibe de src/academy-learning-card.js y qué deja preparado para academy-learning-card.js. En Coverage útil por archivo, demo/index.html queda intacto para comprobar el contrato desde fuera.

La última parada es academy-learning-card.js. Este archivo registra el tag público que una aplicación puede instanciar. Compáralo con demo/index.html: deben colaborar sin duplicar responsabilidades. academy-learning-card.js actúa como consumidor del cambio y no necesita otra edición en este paso.

Ya está conectado el recorrido. La comprobación importante es esta: La interfaz diferencia cobertura de líneas y cobertura de contratos públicos, con archivos y denominadores visibles. Si el preview contradice tu predicción sobre Coverage útil por archivo, vuelve al último archivo editado y sigue su salida hasta el consumidor.

Ahora piensa en el caso que suele romper este contrato: Celebrar 100% con aserciones débiles crea falsa seguridad; introduce un defecto y verifica que al menos una prueba falle. En Coverage útil por archivo, propón una causa, cambia una sola frontera y usa el preview o las pruebas para refutarla.

A continuación podrás repasar el modelo con calma sobre Coverage útil por archivo. Después, el proyecto de Coverage útil por archivo se abrirá completo para que experimentes y compares soluciones equivalentes sin recibir una línea para copiar.
