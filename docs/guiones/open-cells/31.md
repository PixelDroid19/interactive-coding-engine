Demo interactiva del componente. La demo es el consumidor humano más pequeño: basic.html presenta el caso mínimo, index.html organiza el laboratorio y demo.js conecta controles, idioma y eventos.

Abrimos demo/index.html. Este archivo presenta controles y una instancia real del paquete. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos demo/index.html: la página contiene controles, una instancia del tag y un output para eventos. El único script propio que carga es demo.js.

Abrimos demo/demo.js. Este archivo consume la entrada pública y conecta propiedades, idioma y eventos. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos demo/demo.js: importamos la entrada pública, buscamos la instancia y conectamos input con una propiedad, select con el idioma y el evento público con el output.

Abrimos demo/demo-build.js. Este archivo actúa como raíz del grafo que construye la demo. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos demo/demo-build.js: este archivo importa demo.js y se convierte en la raíz explícita del grafo que Vite construye para distribución.

Abrimos academy-learning-card.js. Este archivo registra el tag público que una aplicación puede instanciar. Observa su entrada y busca qué otro archivo lo consume.

Ejecutamos el proyecto después de conectar sus archivos. La evidencia que buscamos es esta: demo.js importa la entrada pública del paquete y permite probar propiedades, eventos y variantes sin editar el componente.

Antes de practicar, contrasta el resultado con este error frecuente: Una demo que replica lógica interna puede verse bien cuando el paquete está roto; importa siempre la entrada pública.
