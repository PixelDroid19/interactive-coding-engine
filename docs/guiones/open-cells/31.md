Demo interactiva del componente. La demo es el consumidor humano más pequeño: basic.html presenta el caso mínimo, index.html organiza el laboratorio y demo.js conecta controles, idioma y eventos. Hoy seguiremos el recorrido demo/index.html → demo/demo.js → demo/demo-build.js → academy-search-filter.js. Para entender Demo interactiva del componente, identificaremos quién posee cada dato, quién consume su salida y qué resultado observable confirma el contrato.

Nuestro punto de partida es demo/index.html. Este archivo presenta controles y una instancia real del paquete. Antes de tocarlo en Demo interactiva del componente, localiza su salida pública y predice quién dependerá de ella.

Aquí hacemos el cambio principal en demo/index.html. La página contiene controles, una instancia del tag y un output para eventos. El único script propio que carga es demo.js. Después lo contrastaremos con demo/demo.js para verificar el contrato desde otro archivo.

Después abrimos demo/demo.js. Este archivo consume la entrada pública y conecta propiedades, idioma y eventos. Revisa qué recibe de demo/index.html y qué deja preparado para demo/demo-build.js.

Vamos a completar demo/demo.js. Importamos la entrada pública, buscamos la instancia y conectamos input con una propiedad, select con el idioma y el evento público con el output. Después lo contrastaremos con demo/demo-build.js para verificar el contrato desde otro archivo.

Seguimos en demo/demo-build.js. Este archivo actúa como raíz del grafo que construye la demo. Revisa qué recibe de demo/demo.js y qué deja preparado para academy-search-filter.js.

Ahora sí editamos demo/demo-build.js. Este archivo importa demo.js y se convierte en la raíz explícita del grafo que Vite construye para distribución. Después lo contrastaremos con academy-search-filter.js para verificar el contrato desde otro archivo.

La última parada es academy-search-filter.js. Este archivo conecta esta responsabilidad con el resto del proyecto. Compáralo con demo/demo-build.js: deben colaborar sin duplicar responsabilidades. academy-search-filter.js actúa como consumidor del cambio y no necesita otra edición en este paso.

Ya está conectado el recorrido. La comprobación importante es esta: demo.js importa la entrada pública del paquete y permite probar propiedades, eventos y variantes sin editar el componente. Si el preview contradice tu predicción sobre Demo interactiva del componente, vuelve al último archivo editado y sigue su salida hasta el consumidor.

Ahora piensa en el caso que suele romper este contrato: Una demo que replica lógica interna puede verse bien cuando el paquete está roto; importa siempre la entrada pública. En Demo interactiva del componente, propón una causa, cambia una sola frontera y usa el preview o las pruebas para refutarla.

A continuación podrás repasar el modelo con calma sobre Demo interactiva del componente. Después, el proyecto de Demo interactiva del componente se abrirá completo para que experimentes y compares soluciones equivalentes sin recibir una línea para copiar.
