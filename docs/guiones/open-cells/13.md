Slots, parts y tokens públicos. La personalización útil expone puntos deliberados: slots para contenido, parts para fragmentos y custom properties para decisiones de tema.

En Slots, parts y tokens públicos, este archivo es la frontera que vamos a observar. No trabaja solo: El componente documenta qué puede insertar o estilizar un consumidor sin atravesar su Shadow DOM.

Haz que el contrato visible respete disabled y conserve loading, empty, error o success. Una entrada desconocida debe producir un estado seguro. Primero aislamos esa decisión en estadoVisible13; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: propiedad pública → estado interno → render e interacción. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. Un selector profundo depende de estructura privada; cambia internamente el markup y comprueba que el contrato público siga estable.

Te devuelvo el punto de partida de Slots, parts y tokens públicos. Predice las tres comprobaciones de estadoVisible13 antes de escribir y corrige una sola causa cada vez.

Después del reto de Slots, parts y tokens públicos, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
