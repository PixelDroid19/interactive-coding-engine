Estado retenido. Un nuevo suscriptor recibe el último valor del canal; eso convierte orden temporal en una decisión de producto.

En Estado retenido, este archivo es la frontera que vamos a observar. No trabaja solo: La prueba cubre publicar antes de suscribir y confirma una única entrega inicial con el valor más reciente.

Elige evento para un árbol cercano, canal para participantes lejanos y navegación cuando la intención cambia de página. Primero aislamos esa decisión en elegirCanal53; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: intención → evento, canal o navegación → consumidor. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. Suponer que solo llegan eventos futuros duplica cargas; ensaya siempre la suscripción tardía.

Te devuelvo el punto de partida de Estado retenido. Predice las tres comprobaciones de elegirCanal53 antes de escribir y corrige una sola causa cada vez.

Después del reto de Estado retenido, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
