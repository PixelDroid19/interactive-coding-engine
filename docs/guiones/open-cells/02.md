Contratos del runtime Cells. Aprende a reconocer qué partes son API pública, qué partes son infraestructura y cómo evitar acoplar una app a detalles internos.

Abrimos package.json. Este archivo declara identidad, entradas, dependencias y comandos que consumen las herramientas. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos package.json: type module permite usar import y export. exports señala la entrada pública; cells.entry señala el bootstrap de una app. Los scripts nombran operaciones reales de desarrollo, pruebas, locales y build.

Abrimos index.js. Este archivo expone la clase sin registrar efectos globales. Observa su entrada y busca qué otro archivo lo consume.

Abrimos academy-learning-card.js. Este archivo registra el tag público que una aplicación puede instanciar. Observa su entrada y busca qué otro archivo lo consume.

Abrimos src/academy-learning-card.js. Este archivo implementa propiedades, render, dependencias scoped y eventos del componente. Observa su entrada y busca qué otro archivo lo consume.

Ejecutamos el proyecto después de conectar sus archivos. La evidencia que buscamos es esta: WidgetMixin aporta idioma y emisión de eventos. ScopedElementsMixin aporta un registro local de dependencias. LitElement conserva renderizado y ciclo reactivo. El orden de composición describe qué capacidad envuelve a cuál y la cadena de super debe permanecer completa.

Antes de practicar, contrasta el resultado con este error frecuente: La plataforma no puede iniciar Node, abrir puertos ni ejecutar npm desde un iframe. El Worker interpreta una lista concreta de comandos, modifica un sistema de archivos virtual y produce preview, pruebas, documentación o ZIP. La interfaz siempre indica cuándo trabaja el Worker y nunca anuncia un servidor inexistente. Un error frecuente consiste en cambiar varias fronteras a la vez; conserva una predicción y comprueba una sola causa antes de continuar.
