Contratos del runtime Cells. Aprende a reconocer qué partes son API pública, qué partes son infraestructura y cómo evitar acoplar una app a detalles internos. Hoy seguiremos el recorrido package.json → index.js → academy-status-badge.js → src/academy-status-badge.js. Para entender Contratos del runtime Cells, identificaremos quién posee cada dato, quién consume su salida y qué resultado observable confirma el contrato.

La primera parada está en package.json. Este archivo declara identidad, entradas, dependencias y comandos que consumen las herramientas. Antes de tocarlo en Contratos del runtime Cells, localiza su salida pública y predice quién dependerá de ella.

Este es el archivo que modificaremos: package.json. Type module permite usar import y export. exports señala la entrada pública; cells.entry señala el bootstrap de una app. Los scripts nombran operaciones reales de desarrollo, pruebas, locales y build. Después lo contrastaremos con index.js para verificar el contrato desde otro archivo.

Ahora pasamos a index.js. Este archivo expone la clase sin registrar efectos globales. Revisa qué recibe de package.json y qué deja preparado para academy-status-badge.js. En Contratos del runtime Cells, index.js queda intacto para comprobar el contrato desde fuera.

Después abrimos academy-status-badge.js. Este archivo conecta esta responsabilidad con el resto del proyecto. Revisa qué recibe de index.js y qué deja preparado para src/academy-status-badge.js. academy-status-badge.js actúa como consumidor del cambio y no necesita otra edición en este paso.

Cerramos el recorrido en src/academy-status-badge.js. Este archivo implementa la API, el render, las dependencias y el evento del artefacto protagonista. Compáralo con academy-status-badge.js: deben colaborar sin duplicar responsabilidades. Solo inspeccionamos src/academy-status-badge.js; cambiarlo también ocultaría la causa del resultado.

Con los archivos enlazados, observa este contrato: WidgetMixin aporta idioma y emisión de eventos. ScopedElementsMixin aporta un registro local de dependencias. LitElement conserva renderizado y ciclo reactivo. El orden de composición describe qué capacidad envuelve a cuál y la cadena de super debe permanecer completa. Si el preview contradice tu predicción sobre Contratos del runtime Cells, vuelve al último archivo editado y sigue su salida hasta el consumidor.

Haz una última predicción sobre este error frecuente: La plataforma no puede iniciar Node, abrir puertos ni ejecutar npm desde un iframe. El Worker interpreta una lista concreta de comandos, modifica un sistema de archivos virtual y produce preview, pruebas, documentación o ZIP. La interfaz siempre indica cuándo trabaja el Worker y nunca anuncia un servidor inexistente. Un error frecuente consiste en cambiar varias fronteras a la vez; conserva una predicción y comprueba una sola causa antes de continuar. En Contratos del runtime Cells, propón una causa, cambia una sola frontera y usa el preview o las pruebas para refutarla.
