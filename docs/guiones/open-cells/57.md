Data manager separado. El data manager posee transporte, cancelación y transformación; la página posee presentación y navegación.

En Data manager separado, este archivo es la frontera que vamos a observar. No trabaja solo: La página observa estados públicos del manager sin construir URLs ni interpretar respuestas crudas.

Acepta datos únicamente cuando pertenecen a la solicitud vigente. Una respuesta antigua debe quedar sin publicar. Primero aislamos esa decisión en aceptarRespuesta57; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: petición → estado → respuesta vigente o descarte → cleanup. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. Un manager que navega o pinta DOM mezcla capas; reemplaza la página por una prueba y verifica que sigue usable.

Te devuelvo el punto de partida de Data manager separado. Predice las tres comprobaciones de aceptarRespuesta57 antes de escribir y corrige una sola causa cada vez.

Después del reto de Data manager separado, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
