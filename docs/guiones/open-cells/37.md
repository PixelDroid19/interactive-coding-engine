Build de demo y resolución de módulos. demo-build.js es el punto de entrada de construcción: desde él se resuelve el controlador, la entrada pública y el grafo del componente.

Abrimos demo/demo-build.js. Este archivo actúa como raíz del grafo que construye la demo. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos demo/demo-build.js: este archivo importa demo.js y se convierte en la raíz explícita del grafo que Vite construye para distribución.

Abrimos demo/demo.js. Este archivo consume la entrada pública y conecta propiedades, idioma y eventos. Observa su entrada y busca qué otro archivo lo consume.

Abrimos academy-learning-card.js. Este archivo registra el tag público que una aplicación puede instanciar. Observa su entrada y busca qué otro archivo lo consume.

Abrimos package.json. Este archivo declara identidad, entradas, dependencias y comandos que consumen las herramientas. Observa su entrada y busca qué otro archivo lo consume.

Ejecutamos el proyecto después de conectar sus archivos. La evidencia que buscamos es esta: Imports locales y permitidos se resuelven, rutas inválidas fallan y la demo ejecuta el mismo módulo que se exporta.

Antes de practicar, contrasta el resultado con este error frecuente: Un preview en blanco sin canal de errores deja al estudiante adivinando; comunica fallo, archivo y causa al host.

La lectura siguiente abre un laboratorio de proyecto para Build de demo y resolución de módulos. Allí corregirás archivos reales, construirás la vista previa y ejecutarás contratos sin recibir una solución copiada.
