Build de demo y resolución de módulos. demo-build.js es el punto de entrada de construcción: desde él se resuelve el controlador, la entrada pública y el grafo del componente. Hoy seguiremos el recorrido demo/demo-build.js → demo/demo.js → academy-learning-card.js → package.json. Para entender Build de demo y resolución de módulos, identificaremos quién posee cada dato, quién consume su salida y qué resultado observable confirma el contrato.

Nuestro punto de partida es demo/demo-build.js. Este archivo actúa como raíz del grafo que construye la demo. Antes de tocarlo en Build de demo y resolución de módulos, localiza su salida pública y predice quién dependerá de ella.

Ahora sí editamos demo/demo-build.js. Este archivo importa demo.js y se convierte en la raíz explícita del grafo que Vite construye para distribución. Después lo contrastaremos con demo/demo.js para verificar el contrato desde otro archivo.

El siguiente enlace aparece en demo/demo.js. Este archivo consume la entrada pública y conecta propiedades, idioma y eventos. Revisa qué recibe de demo/demo-build.js y qué deja preparado para academy-learning-card.js. Solo inspeccionamos demo/demo.js; cambiarlo también ocultaría la causa del resultado.

Ahora pasamos a academy-learning-card.js. Este archivo registra el tag público que una aplicación puede instanciar. Revisa qué recibe de demo/demo.js y qué deja preparado para package.json. En Build de demo y resolución de módulos, academy-learning-card.js queda intacto para comprobar el contrato desde fuera.

La última parada es package.json. Este archivo declara identidad, entradas, dependencias y comandos que consumen las herramientas. Compáralo con academy-learning-card.js: deben colaborar sin duplicar responsabilidades. package.json actúa como consumidor del cambio y no necesita otra edición en este paso.

Ya está conectado el recorrido. La comprobación importante es esta: Imports locales y permitidos se resuelven, rutas inválidas fallan y la demo ejecuta el mismo módulo que se exporta. Si el preview contradice tu predicción sobre Build de demo y resolución de módulos, vuelve al último archivo editado y sigue su salida hasta el consumidor.

Ahora piensa en el caso que suele romper este contrato: Un preview en blanco sin canal de errores deja al estudiante adivinando; comunica fallo, archivo y causa al host. En Build de demo y resolución de módulos, propón una causa, cambia una sola frontera y usa el preview o las pruebas para refutarla.
