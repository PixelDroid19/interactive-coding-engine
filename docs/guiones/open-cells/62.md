Cleanup del data manager. Al salir, la página corta tanto la fuente de datos como la ruta que entregaría sus resultados.

Abrimos app/data/academy-product-data-manager.js. Este archivo posee petición, estados, carreras y cancelación. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos app/data/academy-product-data-manager.js: requestId identifica la petición vigente, AbortController permite cancelarla y emit diferencia loading, success, empty y error.

Abrimos app/pages/academy-home-page/academy-home-page.js. Este archivo coordina componentes, ciclo de página y navegación. Observa su entrada y busca qué otro archivo lo consume.

Abrimos test/unit/app.test.js. Este archivo comprueba la historia vertical desde rutas y páginas hasta datos. Observa su entrada y busca qué otro archivo lo consume.

Abrimos package.json. Este archivo declara identidad, entradas, dependencias y comandos que consumen las herramientas. Observa su entrada y busca qué otro archivo lo consume.

Ejecutamos el proyecto después de conectar sus archivos. La evidencia que buscamos es esta: disconnect aborta la petición activa y no se publica ningún estado posterior a onPageLeave.

Antes de practicar, contrasta el resultado con este error frecuente: Eliminar el elemento sin abortar permite que un callback retenga memoria; observa listeners y señales después del desmontaje.

La lectura siguiente abre un laboratorio de proyecto para Cleanup del data manager. Allí corregirás archivos reales, construirás la vista previa y ejecutarás contratos sin recibir una solución copiada.
