Cleanup del data manager. Al salir, la página corta tanto la fuente de datos como la ruta que entregaría sus resultados.

En Cleanup del data manager, este archivo es la frontera que vamos a observar. No trabaja solo: disconnect aborta la petición activa y no se publica ningún estado posterior a onPageLeave.

Acepta datos únicamente cuando pertenecen a la solicitud vigente. Una respuesta antigua debe quedar sin publicar. Primero aislamos esa decisión en aceptarRespuesta62; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: petición → estado → respuesta vigente o descarte → cleanup. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. Eliminar el elemento sin abortar permite que un callback retenga memoria; observa listeners y señales después del desmontaje.

Te devuelvo el punto de partida de Cleanup del data manager. Predice las tres comprobaciones de aceptarRespuesta62 antes de escribir y corrige una sola causa cada vez.

Después del reto de Cleanup del data manager, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
