Tests de aplicación. Una prueba de app recorre una historia vertical: página inicial, evento de hijo, canal, navegación, parámetros y cleanup. Hoy seguiremos el recorrido test/unit/app.test.js → app/scripts/app-routes.js → app/pages/academy-home-page/academy-home-page.js → app/data/academy-product-data-manager.js. Para entender Tests de aplicación, identificaremos quién posee cada dato, quién consume su salida y qué resultado observable confirma el contrato.

Empezamos por test/unit/app.test.js. Este archivo comprueba la historia vertical desde rutas y páginas hasta datos. Antes de tocarlo en Tests de aplicación, localiza su salida pública y predice quién dependerá de ella.

Aquí hacemos el cambio principal en test/unit/app.test.js. Las pruebas conectan rutas, páginas y data manager con valores variables; además verifican cleanup y respuestas antiguas. Después lo contrastaremos con app/scripts/app-routes.js para verificar el contrato desde otro archivo.

Después abrimos app/scripts/app-routes.js. Este archivo relaciona URL, nombre estable, tag de página y carga lazy. Revisa qué recibe de test/unit/app.test.js y qué deja preparado para app/pages/academy-home-page/academy-home-page.js.

Vamos a completar app/scripts/app-routes.js. Cada objeto separa path de URL, name estable, component que se monta y action que importa la página solo cuando se visita. Después lo contrastaremos con app/pages/academy-home-page/academy-home-page.js para verificar el contrato desde otro archivo.

Seguimos en app/pages/academy-home-page/academy-home-page.js. Este archivo coordina componentes, ciclo de página y navegación. Revisa qué recibe de app/scripts/app-routes.js y qué deja preparado para app/data/academy-product-data-manager.js.

Ahora sí editamos app/pages/academy-home-page/academy-home-page.js. PageMixin aporta navegación y canales; ScopedElementsMixin resuelve la tarjeta. onPageEnter adquiere recursos, onPageLeave los libera y render conserva UI declarativa. Después lo contrastaremos con app/data/academy-product-data-manager.js para verificar el contrato desde otro archivo.

Terminamos en app/data/academy-product-data-manager.js. Este archivo posee petición, estados, carreras y cancelación. Compáralo con app/pages/academy-home-page/academy-home-page.js: deben colaborar sin duplicar responsabilidades. En Tests de aplicación, app/data/academy-product-data-manager.js queda intacto para comprobar el contrato desde fuera.

Ejecutamos el proyecto y buscamos una señal concreta: El runner monta un outlet aislado y comprueba resultados visibles además de contratos intermedios. Si el preview contradice tu predicción sobre Tests de aplicación, vuelve al último archivo editado y sigue su salida hasta el consumidor.

Antes del ejercicio, intenta explicar este fallo: Probar piezas verdes por separado no garantiza integración; rompe el nombre de ruta y exige que el flujo falle. En Tests de aplicación, propón una causa, cambia una sola frontera y usa el preview o las pruebas para refutarla.

La lectura siguiente organiza lo que acabamos de ver sobre Tests de aplicación. Después, el proyecto de Tests de aplicación se abrirá completo para que experimentes y compares soluciones equivalentes sin recibir una línea para copiar.
