Tests de aplicación. Una prueba de app recorre una historia vertical: página inicial, evento de hijo, canal, navegación, parámetros y cleanup.

En Tests de aplicación, este archivo es la frontera que vamos a observar. No trabaja solo: El runner monta un outlet aislado y comprueba resultados visibles además de contratos intermedios.

Valida una entrega completa: ZIP estándar, pruebas, build y ausencia de secretos. Un archivo descargado por sí solo no basta. Primero aislamos esa decisión en validarEntrega63; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: workspace limpio → test y build → ZIP → continuación con CLI. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. Probar piezas verdes por separado no garantiza integración; rompe el nombre de ruta y exige que el flujo falle.

Te devuelvo el punto de partida de Tests de aplicación. Predice las tres comprobaciones de validarEntrega63 antes de escribir y corrige una sola causa cada vez.

Después del reto de Tests de aplicación, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
