Tests de aplicación. Una prueba de app recorre una historia vertical: página inicial, evento de hijo, canal, navegación, parámetros y cleanup.

Abrimos test/unit/app.test.js. Este archivo comprueba la historia vertical desde rutas y páginas hasta datos. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos test/unit/app.test.js: las pruebas conectan rutas, páginas y data manager con valores variables; además verifican cleanup y respuestas antiguas.

Abrimos app/scripts/app-routes.js. Este archivo relaciona URL, nombre estable, tag de página y carga lazy. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos app/scripts/app-routes.js: cada objeto separa path de URL, name estable, component que se monta y action que importa la página solo cuando se visita.

Abrimos app/pages/academy-home-page/academy-home-page.js. Este archivo coordina componentes, ciclo de página y navegación. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos app/pages/academy-home-page/academy-home-page.js: PageMixin aporta navegación y canales; ScopedElementsMixin resuelve la tarjeta. onPageEnter adquiere recursos, onPageLeave los libera y render conserva UI declarativa.

Abrimos app/data/academy-product-data-manager.js. Este archivo posee petición, estados, carreras y cancelación. Observa su entrada y busca qué otro archivo lo consume.

Ejecutamos el proyecto después de conectar sus archivos. La evidencia que buscamos es esta: El runner monta un outlet aislado y comprueba resultados visibles además de contratos intermedios.

Antes de practicar, contrasta el resultado con este error frecuente: Probar piezas verdes por separado no garantiza integración; rompe el nombre de ruta y exige que el flujo falle.

La lectura siguiente abre un laboratorio de proyecto para Tests de aplicación. Allí corregirás archivos reales, construirás la vista previa y ejecutarás contratos sin recibir una solución copiada.
