Exportar un componente consumible. La exportación es exitosa cuando otro proyecto puede instalar, importar y usar el paquete sin conocer el curso.

En Exportar un componente consumible, este archivo es la frontera que vamos a observar. No trabaja solo: El ZIP conserva rutas, package.json, entrada, tipos, locales, tests, demo y metadata; una herramienta ZIP estándar lo valida.

Consulta la parte de la API pública solicitada. La comprobación debe aceptar valores distintos y no depender del orden del objeto. Primero aislamos esa decisión en leerApiPublica38; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: entrada pública → consumidor real → evidencia repetible. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. Comprobar solo que existe un Blob no prueba el archivo; abre el ZIP y verifica CRC, nombres y contenido.

Te devuelvo el punto de partida de Exportar un componente consumible. Predice las tres comprobaciones de leerApiPublica38 antes de escribir y corrige una sola causa cada vez.

Después del reto de Exportar un componente consumible, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
