Exportar un componente consumible. La exportación es exitosa cuando otro proyecto puede instalar, importar y usar el paquete sin conocer el curso.

Abrimos package.json. Este archivo declara identidad, entradas, dependencias y comandos que consumen las herramientas. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos package.json: type module permite usar import y export. exports señala la entrada pública; cells.entry señala el bootstrap de una app. Los scripts nombran operaciones reales de desarrollo, pruebas, locales y build.

Abrimos index.js. Este archivo expone la clase sin registrar efectos globales. Observa su entrada y busca qué otro archivo lo consume.

Abrimos custom-elements.json. Este archivo describe la API para herramientas sin ejecutar el módulo. Observa su entrada y busca qué otro archivo lo consume.

Abrimos README.md. Este archivo explica cómo consumir, probar y continuar el proyecto fuera del curso. Observa su entrada y busca qué otro archivo lo consume.

Ejecutamos el proyecto después de conectar sus archivos. La evidencia que buscamos es esta: El ZIP conserva rutas, package.json, entrada, tipos, locales, tests, demo y metadata; una herramienta ZIP estándar lo valida.

Antes de practicar, contrasta el resultado con este error frecuente: Comprobar solo que existe un Blob no prueba el archivo; abre el ZIP y verifica CRC, nombres y contenido.
