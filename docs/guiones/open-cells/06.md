Crear tu primer componente Cells. Aplica el modelo completo: dependencia scoped, texto traducible, evento público, preview aislado, pruebas de contrato y exportación. Hoy seguiremos el recorrido src/academy-product-card.js → src/mixins/WidgetMixin.js → demo/demo.js → test/unit/academy-product-card.test.js. Para entender Crear tu primer componente Cells, identificaremos quién posee cada dato, quién consume su salida y qué resultado observable confirma el contrato.

Empezamos por src/academy-product-card.js. Este archivo implementa la API, el render, las dependencias y el evento del artefacto protagonista. Antes de tocarlo en Crear tu primer componente Cells, localiza su salida pública y predice quién dependerá de ella.

Este es el archivo que modificaremos: src/academy-product-card.js. Conectamos propiedades, traducciones, composición scoped y una salida observable sin copiar las dependencias reutilizadas. Después lo contrastaremos con src/mixins/WidgetMixin.js para verificar el contrato desde otro archivo.

Ahora pasamos a src/mixins/WidgetMixin.js. Este archivo concentra traducción y emisión de intenciones públicas. Revisa qué recibe de src/academy-product-card.js y qué deja preparado para demo/demo.js. src/mixins/WidgetMixin.js actúa como consumidor del cambio y no necesita otra edición en este paso.

Después abrimos demo/demo.js. Este archivo consume la entrada pública y conecta propiedades, idioma y eventos. Revisa qué recibe de src/mixins/WidgetMixin.js y qué deja preparado para test/unit/academy-product-card.test.js. Solo inspeccionamos demo/demo.js; cambiarlo también ocultaría la causa del resultado.

Terminamos en test/unit/academy-product-card.test.js. Este archivo conecta esta responsabilidad con el resto del proyecto. Compáralo con demo/demo.js: deben colaborar sin duplicar responsabilidades. En Crear tu primer componente Cells, test/unit/academy-product-card.test.js queda intacto para comprobar el contrato desde fuera.

Ejecutamos el proyecto y buscamos una señal concreta: El botón ya está importado. La tarea consiste en conectarlo al registro scoped de este host. Así dos árboles pueden resolver una misma etiqueta con implementaciones distintas sin contaminar customElements global. Si el preview contradice tu predicción sobre Crear tu primer componente Cells, vuelve al último archivo editado y sigue su salida hasta el consumidor.

Antes del ejercicio, intenta explicar este fallo: La acción debe salir mediante emitEvent con un detail útil. El nombre final incorpora el tag del host; el consumidor escucha el evento público sin llamar métodos internos. Las comprobaciones aceptan cualquier nombre de estudiante y verifican el contrato, no un valor fijo. Un error frecuente consiste en cambiar varias fronteras a la vez; conserva una predicción y comprueba una sola causa antes de continuar. En Crear tu primer componente Cells, propón una causa, cambia una sola frontera y usa el preview o las pruebas para refutarla.
