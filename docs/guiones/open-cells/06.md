Vamos a crear el componente archivo por archivo. Empezamos por el paquete, seguimos sus entradas hasta la clase, añadimos locales y terminamos consumiéndolo desde una demo real.

package.json da identidad al paquete. type module habilita import y export; exports declara las entradas públicas; los scripts conservan desarrollo, pruebas, locales, documentación y build.

index.js exporta la clase desde src sin registrar todavía el tag. Esto permite importar la clase en pruebas o en composición avanzada sin ejecutar un efecto global.

La segunda entrada importa la clase y registra academy-learning-card si el tag aún no existe. Esta es la superficie sencilla que normalmente consume una aplicación.

Ahora construimos la clase. LitElement renderiza, ScopedElementsMixin resuelve dependencias locales y WidgetMixin aporta traducción y eventos. properties define learnerName como entrada pública.

locales.json es la fuente de idioma del componente. Inglés y español repiten claves y placeholders; el template solicita esas claves con this.t en lugar de guardar frases sueltas.

La demo crea controles, instancia el tag público y reserva un output para observar eventos. No copia la implementación del componente.

demo.js importa la entrada pública, asigna learnerName cuando cambia el input, actualiza el idioma y escucha academy-learning-card-continue como lo haría una aplicación.

Ejecutamos después de conectar el grafo completo. La vista debe mostrar el nombre, cambiar idioma y devolver el evento sin que la demo conozca métodos privados.

Retiro únicamente el registro del botón y la emisión pública. El resto del proyecto permanece para que puedas seguir imports, template, locales y consumidor antes de corregir.

La lectura siguiente repasa el recorrido completo y abre el mismo proyecto para probar idioma, evento, cobertura y exportación.
