Estados loading, empty, error y success. Una petición no produce solo datos: produce transiciones que la interfaz debe representar sin mezclar estados incompatibles.

En Estados loading, empty, error y success, este archivo es la frontera que vamos a observar. No trabaja solo: En cada instante existe un estado principal y su información asociada; success tiene datos, empty confirma una respuesta válida sin elementos y error permite recuperación.

Haz que el contrato visible respete disabled y conserve loading, empty, error o success. Una entrada desconocida debe producir un estado seguro. Primero aislamos esa decisión en estadoVisible12; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: propiedad pública → estado interno → render e interacción. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. Usar una sola bandera loading suele dejar errores viejos junto a resultados nuevos; dibuja la tabla de transiciones antes de renderizar.

Te devuelvo el punto de partida de Estados loading, empty, error y success. Predice las tres comprobaciones de estadoVisible12 antes de escribir y corrige una sola causa cada vez.

Después del reto de Estados loading, empty, error y success, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
