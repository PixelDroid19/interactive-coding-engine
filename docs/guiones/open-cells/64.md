Locales de aplicación. El shell decide idioma y las páginas consumen el mismo contrato de recursos sin duplicar catálogos por componente.

En Locales de aplicación, este archivo es la frontera que vamos a observar. No trabaja solo: Cambio de idioma actualiza la página activa y una página lazy carga su texto correcto al entrar después.

Valida una entrega completa: ZIP estándar, pruebas, build y ausencia de secretos. Un archivo descargado por sí solo no basta. Primero aislamos esa decisión en validarEntrega64; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: workspace limpio → test y build → ZIP → continuación con CLI. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. Precargar solo la página inicial deja huecos al navegar; prueba una ruta que todavía no se había importado.

Te devuelvo el punto de partida de Locales de aplicación. Predice las tres comprobaciones de validarEntrega64 antes de escribir y corrige una sola causa cada vez.

Después del reto de Locales de aplicación, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
