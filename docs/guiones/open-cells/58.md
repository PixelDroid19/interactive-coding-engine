Transiciones de una petición. Una petición es una máquina de estados: idle → loading → success, empty o error, con retry y cancelación posibles.

En Transiciones de una petición, este archivo es la frontera que vamos a observar. No trabaja solo: Cada transición limpia datos incompatibles y produce una salida observable única.

Acepta datos únicamente cuando pertenecen a la solicitud vigente. Una respuesta antigua debe quedar sin publicar. Primero aislamos esa decisión en aceptarRespuesta58; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: petición → estado → respuesta vigente o descarte → cleanup. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. Actualizar error sin retirar loading deja dos verdades; usa una tabla de estado y revisa cada salida.

Te devuelvo el punto de partida de Transiciones de una petición. Predice las tres comprobaciones de aceptarRespuesta58 antes de escribir y corrige una sola causa cada vez.

Después del reto de Transiciones de una petición, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
