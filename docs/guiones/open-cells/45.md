onPageEnter y parámetros. onPageEnter inicia trabajo cada vez que la página se vuelve activa y recibe los parámetros de navegación. Hoy seguiremos el recorrido app/pages/academy-cart-page/academy-cart-page.js → app/scripts/app-routes.js → app/pages/academy-product-detail-page/academy-product-detail-page.js → app/pages/academy-home-page/academy-home-page.js. Para entender onPageEnter y parámetros, identificaremos quién posee cada dato, quién consume su salida y qué resultado observable confirma el contrato.

Empezamos por app/pages/academy-cart-page/academy-cart-page.js. Este archivo posee los elementos del carrito y deriva el total visible. Antes de tocarlo en onPageEnter y parámetros, localiza su salida pública y predice quién dependerá de ella.

Ahora sí editamos app/pages/academy-cart-page/academy-cart-page.js. Los items son estado de página y total es un dato derivado en render; ninguna tarjeta global conserva el carrito. Después lo contrastaremos con app/scripts/app-routes.js para verificar el contrato desde otro archivo.

El siguiente enlace aparece en app/scripts/app-routes.js. Este archivo relaciona URL, nombre estable, tag de página y carga lazy. Revisa qué recibe de app/pages/academy-cart-page/academy-cart-page.js y qué deja preparado para app/pages/academy-product-detail-page/academy-product-detail-page.js. app/scripts/app-routes.js actúa como consumidor del cambio y no necesita otra edición en este paso.

Ahora pasamos a app/pages/academy-product-detail-page/academy-product-detail-page.js. Este archivo recibe parámetros de una visita y renderiza el detalle. Revisa qué recibe de app/scripts/app-routes.js y qué deja preparado para app/pages/academy-home-page/academy-home-page.js. Solo inspeccionamos app/pages/academy-product-detail-page/academy-product-detail-page.js; cambiarlo también ocultaría la causa del resultado.

Terminamos en app/pages/academy-home-page/academy-home-page.js. Este archivo coordina componentes, ciclo de página y navegación. Compáralo con app/pages/academy-product-detail-page/academy-product-detail-page.js: deben colaborar sin duplicar responsabilidades. En onPageEnter y parámetros, app/pages/academy-home-page/academy-home-page.js queda intacto para comprobar el contrato desde fuera.

Ejecutamos el proyecto y buscamos una señal concreta: La página reinicia estado transitorio, valida params y comienza recursos que necesita para esa visita. Si el preview contradice tu predicción sobre onPageEnter y parámetros, vuelve al último archivo editado y sigue su salida hasta el consumidor.

Antes del ejercicio, intenta explicar este fallo: Usar constructor para params funciona solo la primera vez; navega dos veces a la misma página con ids distintos. En onPageEnter y parámetros, propón una causa, cambia una sola frontera y usa el preview o las pruebas para refutarla.
