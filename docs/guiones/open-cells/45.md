onPageEnter y parámetros. onPageEnter inicia trabajo cada vez que la página se vuelve activa y recibe los parámetros de navegación.

En onPageEnter y parámetros, este archivo es la frontera que vamos a observar. No trabaja solo: La página reinicia estado transitorio, valida params y comienza recursos que necesita para esa visita.

Devuelve la ruta cuyo name coincide con la intención recibida. No uses el path como sustituto ni elijas siempre la primera ruta. Primero aislamos esa decisión en resolverRuta45; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: ruta → página activa → entrada y cleanup. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. Usar constructor para params funciona solo la primera vez; navega dos veces a la misma página con ids distintos.

Te devuelvo el punto de partida de onPageEnter y parámetros. Predice las tres comprobaciones de resolverRuta45 antes de escribir y corrige una sola causa cada vez.

Después del reto de onPageEnter y parámetros, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
