Crear una app Cells. Una app Cells coordina páginas, rutas, canales, configuración y servicios; no es un componente enorme con muchos if. Hoy seguiremos el recorrido package.json → index.html → app/scripts/app.js → app/scripts/app-routes.js → app/pages/academy-home-page/academy-home-page.js. Para entender Crear una app Cells, identificaremos quién posee cada dato, quién consume su salida y qué resultado observable confirma el contrato.

Empezamos por package.json. Este archivo declara identidad, entradas, dependencias y comandos que consumen las herramientas. Antes de tocarlo en Crear una app Cells, localiza su salida pública y predice quién dependerá de ella.

Aquí hacemos el cambio principal en package.json. Type module permite usar import y export. exports señala la entrada pública; cells.entry señala el bootstrap de una app. Los scripts nombran operaciones reales de desarrollo, pruebas, locales y build. Después lo contrastaremos con index.html para verificar el contrato desde otro archivo.

Después abrimos index.html. Este archivo crea la raíz que el runtime montará en el navegador. Revisa qué recibe de package.json y qué deja preparado para app/scripts/app.js.

Vamos a completar index.html. El main con id app es el outlet. El script type module carga app/scripts/app.js; el nombre del id debe coincidir después con mainNode. Después lo contrastaremos con app/scripts/app.js para verificar el contrato desde otro archivo.

Seguimos en app/scripts/app.js. Este archivo arranca una única instancia del runtime con outlet, rutas e inicio. Revisa qué recibe de index.html y qué deja preparado para app/scripts/app-routes.js.

Ahora sí editamos app/scripts/app.js. Importamos startApp y ROUTES. mainNode coincide con el outlet HTML, initialTemplate coincide con el name de una ruta y el bootstrap ocurre una sola vez. Después lo contrastaremos con app/scripts/app-routes.js para verificar el contrato desde otro archivo.

El siguiente enlace aparece en app/scripts/app-routes.js. Este archivo relaciona URL, nombre estable, tag de página y carga lazy. Revisa qué recibe de app/scripts/app.js y qué deja preparado para app/pages/academy-home-page/academy-home-page.js.

Este es el archivo que modificaremos: app/scripts/app-routes.js. Cada objeto separa path de URL, name estable, component que se monta y action que importa la página solo cuando se visita. Después lo contrastaremos con app/pages/academy-home-page/academy-home-page.js para verificar el contrato desde otro archivo.

La última parada es app/pages/academy-home-page/academy-home-page.js. Este archivo coordina componentes, ciclo de página y navegación. Compáralo con app/scripts/app-routes.js: deben colaborar sin duplicar responsabilidades.

Aquí hacemos el cambio principal en app/pages/academy-home-page/academy-home-page.js. PageMixin aporta navegación y canales; ScopedElementsMixin resuelve la tarjeta. onPageEnter adquiere recursos, onPageLeave los libera y render conserva UI declarativa. Con este cambio ya podremos ejecutar el recorrido y observar su resultado.

Ejecutamos el proyecto y buscamos una señal concreta: El scaffold separa app/scripts, pages, components, data, config y tests. Los textos globales viven en app/locales-app y los propios de una página dentro de la carpeta de esa página. Si el preview contradice tu predicción sobre Crear una app Cells, vuelve al último archivo editado y sigue su salida hasta el consumidor.

Antes del ejercicio, intenta explicar este fallo: Comenzar copiando una app completa oculta responsabilidades; recorre primero quién importa y quién llama cada pieza. En Crear una app Cells, propón una causa, cambia una sola frontera y usa el preview o las pruebas para refutarla.
