Propiedades públicas y estado interno. Una propiedad pública es una entrada del componente; el estado interno describe cómo trabaja para producir una salida.

En Propiedades públicas y estado interno, este archivo es la frontera que vamos a observar. No trabaja solo: El consumidor puede configurar propiedades documentadas, mientras detalles de selección temporal o petición permanecen internos.

Haz que el contrato visible respete disabled y conserve loading, empty, error o success. Una entrada desconocida debe producir un estado seguro. Primero aislamos esa decisión en estadoVisible10; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: propiedad pública → estado interno → render e interacción. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. Exponer cada variable como propiedad crea una API accidental; pregunta si un consumidor necesita controlarla o solo observar el resultado.

Te devuelvo el punto de partida de Propiedades públicas y estado interno. Predice las tres comprobaciones de estadoVisible10 antes de escribir y corrige una sola causa cada vez.

Después del reto de Propiedades públicas y estado interno, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
