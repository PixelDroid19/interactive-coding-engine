Configuración dev y prod. Configuración cambia valores de entorno; no debe cambiar las reglas de negocio ni exigir editar fuentes. Hoy seguiremos el recorrido app/scripts/app.js → package.json → app/config/dev.js → app/config/prod.js. Para entender Configuración dev y prod, identificaremos quién posee cada dato, quién consume su salida y qué resultado observable confirma el contrato.

La primera parada está en app/scripts/app.js. Este archivo arranca una única instancia del runtime con outlet, rutas e inicio. Antes de tocarlo en Configuración dev y prod, localiza su salida pública y predice quién dependerá de ella.

Ahora sí editamos app/scripts/app.js. Importamos startApp y ROUTES. mainNode coincide con el outlet HTML, initialTemplate coincide con el name de una ruta y el bootstrap ocurre una sola vez. Después lo contrastaremos con package.json para verificar el contrato desde otro archivo.

El siguiente enlace aparece en package.json. Este archivo declara identidad, entradas, dependencias y comandos que consumen las herramientas. Revisa qué recibe de app/scripts/app.js y qué deja preparado para app/config/dev.js. En Configuración dev y prod, package.json queda intacto para comprobar el contrato desde fuera.

Ahora pasamos a app/config/dev.js. Este archivo declara valores observables del entorno de desarrollo. Revisa qué recibe de package.json y qué deja preparado para app/config/prod.js. app/config/dev.js actúa como consumidor del cambio y no necesita otra edición en este paso.

Cerramos el recorrido en app/config/prod.js. Este archivo declara una entrega reproducible sin opciones de depuración. Compáralo con app/config/dev.js: deben colaborar sin duplicar responsabilidades. Solo inspeccionamos app/config/prod.js; cambiarlo también ocultaría la causa del resultado.

Con los archivos enlazados, observa este contrato: Cada entorno declara API, logging y flags esperados, y producción no hereda opciones de depuración. Si el preview contradice tu predicción sobre Configuración dev y prod, vuelve al último archivo editado y sigue su salida hasta el consumidor.

Haz una última predicción sobre este error frecuente: Leer process.env dentro del navegador falla o se reemplaza tarde; importa una configuración generada y verificable. En Configuración dev y prod, propón una causa, cambia una sola frontera y usa el preview o las pruebas para refutarla.
