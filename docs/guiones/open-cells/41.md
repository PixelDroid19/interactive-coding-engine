Configuración dev y prod. Configuración cambia valores de entorno; no debe cambiar las reglas de negocio ni exigir editar fuentes. Hoy seguiremos el recorrido package.json → app/config/dev.js → app/config/prod.js → app/scripts/app.js. Para entender Configuración dev y prod, identificaremos quién posee cada dato, quién consume su salida y qué resultado observable confirma el contrato.

La primera parada está en package.json. Este archivo declara identidad, entradas, dependencias y comandos que consumen las herramientas. Antes de tocarlo en Configuración dev y prod, localiza su salida pública y predice quién dependerá de ella. Solo inspeccionamos package.json; cambiarlo también ocultaría la causa del resultado.

El siguiente enlace aparece en app/config/dev.js. Este archivo declara valores observables del entorno de desarrollo. Revisa qué recibe de package.json y qué deja preparado para app/config/prod.js. En Configuración dev y prod, app/config/dev.js queda intacto para comprobar el contrato desde fuera.

Ahora pasamos a app/config/prod.js. Este archivo declara una entrega reproducible sin opciones de depuración. Revisa qué recibe de app/config/dev.js y qué deja preparado para app/scripts/app.js. app/config/prod.js actúa como consumidor del cambio y no necesita otra edición en este paso.

Cerramos el recorrido en app/scripts/app.js. Este archivo arranca una única instancia del runtime con outlet, rutas e inicio. Compáralo con app/config/prod.js: deben colaborar sin duplicar responsabilidades.

Vamos a completar app/scripts/app.js. Importamos startApp y ROUTES. mainNode coincide con el outlet HTML, initialTemplate coincide con el name de una ruta y el bootstrap ocurre una sola vez. Con este cambio ya podremos ejecutar el recorrido y observar su resultado.

Con los archivos enlazados, observa este contrato: Cada entorno declara API, logging y flags esperados, y producción no hereda opciones de depuración. Si el preview contradice tu predicción sobre Configuración dev y prod, vuelve al último archivo editado y sigue su salida hasta el consumidor.

Haz una última predicción sobre este error frecuente: Leer process.env dentro del navegador falla o se reemplaza tarde; importa una configuración generada y verificable. En Configuración dev y prod, propón una causa, cambia una sola frontera y usa el preview o las pruebas para refutarla.

El siguiente paso separa explicación y práctica sobre Configuración dev y prod. Después, el proyecto de Configuración dev y prod se abrirá completo para que experimentes y compares soluciones equivalentes sin recibir una línea para copiar.
