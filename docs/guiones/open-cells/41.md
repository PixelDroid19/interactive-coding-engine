Configuración dev y prod. Configuración cambia valores de entorno; no debe cambiar las reglas de negocio ni exigir editar fuentes.

Abrimos package.json. Este archivo declara identidad, entradas, dependencias y comandos que consumen las herramientas. Observa su entrada y busca qué otro archivo lo consume.

Abrimos app/config/dev.js. Este archivo declara valores observables del entorno de desarrollo. Observa su entrada y busca qué otro archivo lo consume.

Abrimos app/config/prod.js. Este archivo declara una entrega reproducible sin opciones de depuración. Observa su entrada y busca qué otro archivo lo consume.

Abrimos app/scripts/app.js. Este archivo arranca una única instancia del runtime con outlet, rutas e inicio. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos app/scripts/app.js: importamos startApp y ROUTES. mainNode coincide con el outlet HTML, initialTemplate coincide con el name de una ruta y el bootstrap ocurre una sola vez.

Ejecutamos el proyecto después de conectar sus archivos. La evidencia que buscamos es esta: Cada entorno declara API, logging y flags esperados, y producción no hereda opciones de depuración.

Antes de practicar, contrasta el resultado con este error frecuente: Leer process.env dentro del navegador falla o se reemplaza tarde; importa una configuración generada y verificable.

La lectura siguiente abre un laboratorio de proyecto para Configuración dev y prod. Allí corregirás archivos reales, construirás la vista previa y ejecutarás contratos sin recibir una solución copiada.
