Documentación y custom-elements.json. La documentación humana explica intención; el manifest ofrece una descripción estructurada a herramientas.

Abrimos custom-elements.json. Este archivo describe la API para herramientas sin ejecutar el módulo. Observa su entrada y busca qué otro archivo lo consume.

Ahora construimos custom-elements.json: modules apunta al archivo fuente; declarations describe clase y tag; exports relaciona la definición pública con esa declaración.

Abrimos src/academy-learning-card.js. Este archivo implementa propiedades, render, dependencias scoped y eventos del componente. Observa su entrada y busca qué otro archivo lo consume.

Abrimos README.md. Este archivo explica cómo consumir, probar y continuar el proyecto fuera del curso. Observa su entrada y busca qué otro archivo lo consume.

Abrimos package.json. Este archivo declara identidad, entradas, dependencias y comandos que consumen las herramientas. Observa su entrada y busca qué otro archivo lo consume.

Ejecutamos el proyecto después de conectar sus archivos. La evidencia que buscamos es esta: Nombre, propiedades, eventos, slots, parts y ejemplos coinciden entre código, README y custom-elements.json.

Antes de practicar, contrasta el resultado con este error frecuente: Generar metadata una vez y olvidarla crea una API fantasma; valida el manifest en cada build.

La lectura siguiente abre un laboratorio de proyecto para Documentación y custom-elements.json. Allí corregirás archivos reales, construirás la vista previa y ejecutarás contratos sin recibir una solución copiada.
