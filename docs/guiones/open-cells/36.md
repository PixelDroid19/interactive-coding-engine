Documentación y custom-elements.json. La documentación humana explica intención; el manifest ofrece una descripción estructurada a herramientas. Hoy seguiremos el recorrido custom-elements.json → src/academy-learning-card.js → README.md → package.json. Para entender Documentación y custom-elements.json, identificaremos quién posee cada dato, quién consume su salida y qué resultado observable confirma el contrato.

Empezamos por custom-elements.json. Este archivo describe la API para herramientas sin ejecutar el módulo. Antes de tocarlo en Documentación y custom-elements.json, localiza su salida pública y predice quién dependerá de ella.

Vamos a completar custom-elements.json. Modules apunta al archivo fuente; declarations describe clase y tag; exports relaciona la definición pública con esa declaración. Después lo contrastaremos con src/academy-learning-card.js para verificar el contrato desde otro archivo.

Seguimos en src/academy-learning-card.js. Este archivo implementa propiedades, render, dependencias scoped y eventos del componente. Revisa qué recibe de custom-elements.json y qué deja preparado para README.md. src/academy-learning-card.js actúa como consumidor del cambio y no necesita otra edición en este paso.

El siguiente enlace aparece en README.md. Este archivo explica cómo consumir, probar y continuar el proyecto fuera del curso. Revisa qué recibe de src/academy-learning-card.js y qué deja preparado para package.json. Solo inspeccionamos README.md; cambiarlo también ocultaría la causa del resultado.

Terminamos en package.json. Este archivo declara identidad, entradas, dependencias y comandos que consumen las herramientas. Compáralo con README.md: deben colaborar sin duplicar responsabilidades. En Documentación y custom-elements.json, package.json queda intacto para comprobar el contrato desde fuera.

Ejecutamos el proyecto y buscamos una señal concreta: Nombre, propiedades, eventos, slots, parts y ejemplos coinciden entre código, README y custom-elements.json. Si el preview contradice tu predicción sobre Documentación y custom-elements.json, vuelve al último archivo editado y sigue su salida hasta el consumidor.

Antes del ejercicio, intenta explicar este fallo: Generar metadata una vez y olvidarla crea una API fantasma; valida el manifest en cada build. En Documentación y custom-elements.json, propón una causa, cambia una sola frontera y usa el preview o las pruebas para refutarla.
