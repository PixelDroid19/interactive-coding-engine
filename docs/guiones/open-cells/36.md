Documentación y custom-elements.json. La documentación humana explica intención; el manifest ofrece una descripción estructurada a herramientas.

En Documentación y custom-elements.json, este archivo es la frontera que vamos a observar. No trabaja solo: Nombre, propiedades, eventos, slots, parts y ejemplos coinciden entre código, README y custom-elements.json.

Consulta la parte de la API pública solicitada. La comprobación debe aceptar valores distintos y no depender del orden del objeto. Primero aislamos esa decisión en leerApiPublica36; después cambiaremos varias entradas para comprobar que no depende de un ejemplo fijo.

La demostración hace visible este modelo: entrada pública → consumidor real → evidencia repetible. Sigue la entrada que cambia y localiza el caso que debe permanecer ausente, bloqueado o rechazado.

Ahora contrasta el resultado con el error frecuente. Generar metadata una vez y olvidarla crea una API fantasma; valida el manifest en cada build.

Te devuelvo el punto de partida de Documentación y custom-elements.json. Predice las tres comprobaciones de leerApiPublica36 antes de escribir y corrige una sola causa cada vez.

Después del reto de Documentación y custom-elements.json, la lectura ampliará el porqué, el razonamiento reconstruirá el flujo y la depuración te pedirá transferirlo a otro programa.
